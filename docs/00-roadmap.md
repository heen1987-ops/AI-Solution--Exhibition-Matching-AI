# 백주대간 초개인화 AI 매칭서비스 — 30단계 통합 설계 로드맵

> 문서 상태: 설계 산출물 추적 기준안 v1.0  
> 기준일: 2026-08-01  
> 상위 문서: [2026 대한민국 백주대간 초개인화 AI 매칭서비스 통합 설계안](./2026-backju-ai-matching-service-design.md)

이 문서는 30개 설계 단계를 하나의 의존성 체계로 관리하고, 단계별 산출물·완료 조건·미결정을 추적하는 인덱스다. 각 상세 문서가 서로 다르면 인터페이스 명세, DB 정의서, 해당 단계 상세설계 순으로 구현 계약을 확인하고 충돌은 의사결정 기록으로 해소한다.

모든 단계의 설계·구현 전에는 [공유 ChatGPT 설계 대화](https://chatgpt.com/share/6a6d8239-5d0c-83ee-a5b5-7505c996e874)를 상위 방향성 기준으로 확인한다. 실행 규칙과 핵심 불변조건은 저장소 루트 `AGENTS.md`에 고정한다.

## 진행 현황

```text
설계 산출물: 전체 30단계 / 산출물 확보 10단계(1~10)
구현: 착수 — FastAPI 기반과 6단계 온톨로지 카탈로그·DB·검증 API 구현
```

여기서 완료는 상세 설계안이 작성되고 기존 문서와 연결됐다는 뜻이다. 개발·현장 검증·이해관계자 승인을 의미하지 않는다.

## 단계 묶음과 의존성

| 묶음 | 단계 | 종료 조건 |
|---|---:|---|
| A. 기반 | 1~5 | 서비스·화면·API·DB·매칭엔진 경계가 일치 |
| B. 매칭 의미체계 | 6~10 | 동일 코드·프로파일·후보·필터 계약으로 테스트 후보 생성 가능 |
| C. 랭킹 품질 | 11~18 | 관람객·바이어·양면·상황·다양성·설명 정책을 오프라인 재현 가능 |
| D. AI·데이터 운영 | 19~24 | 구조화·임베딩·오케스트레이션·파이프라인·버전 배포 가능 |
| E. 행사 운영·출시 | 25~30 | 분석·운영·보안·인프라·실증·출시 관문 통과 |

```text
6 온톨로지
├─→ 7 사용자 프로파일 ─┐
└─→ 8 업체·제품 프로파일 ├─→ 9 후보검색 ─→ 10 필수필터
                        └─→ 11·12 점수 ─→ 13 양면 적합도
13 ─→ 14 상황 재정렬 ─→ 15 다양성·공정성 ─→ 18 추천 이유
7·8·18 ─→ 19·20·21 ─→ 22 오케스트레이션 ─→ 23·24 운영화
전 단계 로그 ─→ 25 분석 ─→ 26 운영 ─→ 27·28 통제 ─→ 29 실증 ─→ 30 출시
```

11단계와 12단계, 19단계와 20단계, 23단계와 24단계는 입력 계약이 고정된 뒤 병렬로 설계할 수 있다.

## 완료 관문: 6단계

### 입력

- 실제 사전등록·참가업체 신청 필드와 승인 데이터
- [DB 정의서의 ontology.taxonomy_version·concept_revision](./db-erd-table-spec.md)
- 5단계의 관람객·바이어 Feature Builder 입력 목록

### 필수 산출물

- 코드체계: 주종, 맛·향, 도수, 가격, 목적, 거래유형, 유통채널, 공급역량, 상담주제
- 계층·동의어·다국어 표기·폐기 및 대체 코드 규칙
- 원천값 매핑표와 미매핑 처리 규칙
- 버전 활성화·마이그레이션·하위호환 정책
- 관람객·바이어·업체·제품별 사용 가능 코드 행렬

### 완료 조건

- 모든 하드 필터와 점수 특성이 표준 코드 또는 명시적 수치형 필드에 연결된다.
- 하나의 원천값이 여러 코드로 해석될 때 승인 절차와 신뢰도가 정의된다.
- 운영 중 코드 변경에도 과거 추천을 재현할 수 있다.
- 미분류 값이 자동으로 운영 검수 큐에 들어간다.

### 구현 산출물

- 정본 카탈로그: `src/meet_ai/ontology/catalog.v1.json`
- 검증·동의어 해석·수치구간 파생: `src/meet_ai/ontology/catalog.py`
- PostgreSQL 계약과 Alembic 연결: `db/migrations/0001_ontology.sql`, `backend/alembic/versions/20260801_0001_0002_ontology.py`
- 조회·정규화 API: `GET/POST /api/v1/ontology/*`
- AI 구조화 경계: `POST /internal/ai/ontology/extract` (Netlify AI Gateway)

9·10단계(후보검색, 필수조건 필터) 설계는 완료됐다. 구현은 7·8단계 프로파일 테이블을 6단계의 `(taxonomy_version_id, concept_id)` 복합 참조로 연결한 뒤, 9단계 후보검색 계약과 10단계 필터 계약 순으로 진행한다. 설계의 다음 단계는 11·12단계(관람객·바이어 매칭점수)다.

## 사이트 검증 기준선

- 행사 일정: 2026.10.9(금)~11(일), 대구 EXCO 3홀 — 실사이트 확인 완료
- `/adm/` 경로: 공개 접근만으로 관리자 데이터 구조를 확정할 수 없음. 계정·내부 API·내보내기 기능은 운영 주체 확인 필요
- 개인정보 수탁자 불일치: 사전등록 폼 동의문("라온비앤피") vs 정식 개인정보취급방침 제4조("㈜더페어스") — 실제로 다름, 주최측이 정비 필요
- 부대행사 메뉴에 기존 "백주대간 셀파"(셀럽 서포터즈 프로그램)가 이미 존재 — 서비스 가칭 "백주 AI 셀파"와 이름 충돌 가능성 (아직 미해결)
