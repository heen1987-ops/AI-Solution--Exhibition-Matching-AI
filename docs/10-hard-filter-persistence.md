# 제10단계 하드필터 평가 이력 구현

## 구현 원칙

하드필터는 점수 항이 아니라 추천 노출 자격이다. 한 번의 평가를
`matching.filter_evaluation`에 저장하고, 각 후보의 최종 통과·탈락 판정을
`matching.filter_result`에 한 건씩 저장한다. 개별 규칙의 모든 통과 로그를 쌓지 않아
데이터 폭증을 피하면서도 점수 계산에 사용된 자격 판정을 재현할 수 있다.

평가와 판정 레코드는 PostgreSQL 트리거로 수정·삭제를 거부한다. 평가에는 프로파일 버전,
정책 버전, 행사 운영상태 스냅샷, 입력 SHA-256 지문, 후보별 데이터 지문과 근거 참조가 남는다.
통과 후보에는 `filter_evaluation_id`가 전달되며, 11~13단계 점수 코어는 이 ID가 없거나
다른 경우 계산을 거부한다.

## 이식성 경계

하드필터는 `backju.kr/adm/`의 PHP 세션, 관리자 DB, 내부 URL을 조회하지 않는다. 사용자 제외,
방문 이력 등 외부 사이트의 상태는 연동 어댑터가 행사·테넌트 경계를 검증한 뒤 UUID 집합과
상황 스냅샷으로 전달한다. 따라서 동일 코어를 API, 웹훅, CSV 가져오기, 임베드 위젯 방식에
그대로 사용할 수 있다.

AI Gateway는 이 단계의 판정에 사용하지 않는다. 향후 비정형 상담 문장의 특징 추출과 추천 이유
초안 생성에만 사용하고, 하드필터·점수·정책 검증은 버전이 고정된 결정적 코드가 담당한다.

## 트랜잭션 계약

서비스는 평가와 후보별 판정을 같은 세션에 추가하고 `flush`까지만 수행한다. 요청 오케스트레이터가
후속 점수 결과와 함께 커밋하므로 중간 성공이 외부에 노출되지 않는다. 저장 오류는 성공으로
삼키지 않으며 전체 요청을 롤백한다.
