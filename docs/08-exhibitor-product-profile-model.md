# 1. 단계 목적

본 단계의 목적은 참가업체와 제품 정보를 단순 소개 콘텐츠가 아니라, 일반 관람객 추천과 바이어 B2B 매칭에 직접 활용할 수 있는 **구조화된 공급 프로파일**로 전환하는 데 있다.

공급 프로파일은 다음 정보를 통합한다.

* 참가업체의 기본정보와 사업역량
* 제품의 주종·맛·향·도수·가격
* 생산량·MOQ·납기·공급지역 등 거래조건
* OEM·PB·수출·독점유통 가능 여부
* 부스의 시음·구매·상담 운영상태
* 담당자의 상담주제와 가능시간
* 데이터 출처·검증상태·최신성
* AI가 추출한 속성과 사람이 승인한 속성
* 행사별 참가정보와 상시 기업정보

# 2. 핵심 설계 판단

## 2.1 업체·제품·부스 분리

참가업체, 제품, 부스는 서로 다른 엔터티로 관리한다.

```text
참가업체
├─ 제품 1
├─ 제품 2
├─ 제품 3
└─ 행사 참가정보
   └─ 부스
```

한 업체가 여러 제품을 보유할 수 있고, 제품별 가격·주종·거래조건이 다를 수 있다. 또한 동일 업체가 행사마다 다른 부스와 운영조건을 가질 수 있다.

따라서 업체 소개정보에 제품과 부스 정보를 모두 넣는 방식은 적용하지 않는다.

---

## 2.2 상시정보와 행사정보 분리

| 구분      | 예시             | 갱신주기  |
| ------- | -------------- | ----- |
| 상시 업체정보 | 회사명, 소재지, 사업유형 | 낮음    |
| 상시 제품정보 | 주종, 도수, 원료     | 중간    |
| 거래정보    | MOQ, 공급가격, 생산량 | 중간~높음 |
| 행사 참가정보 | 전시제품, 프로모션     | 행사별   |
| 현장 운영정보 | 혼잡, 품절, 시음 가능  | 실시간   |

---

## 2.3 공개정보와 비공개 거래정보 분리

모든 업체정보를 일반 관람객과 바이어에게 동일하게 노출하지 않는다.

### 공개정보

* 업체명
* 브랜드명
* 업체 소개
* 제품명
* 제품 이미지
* 주종
* 도수
* 소비자가
* 시음·구매 가능 여부
* 부스번호

### 인증 바이어 공개정보

* 취급 가능 유통채널
* 공급지역
* MOQ 범위
* 월 생산 가능량 범주
* OEM·PB 가능 여부
* 수출 가능 여부
* 상담주제

### 상담 수락 이후 공개정보

* 상세 공급가격
* 담당자 연락처
* 구체적 납기
* 제품별 재고
* 거래계약 조건
* 샘플 제공 조건

---

## 2.4 미등록과 불가능 분리

업체가 거래조건을 입력하지 않았다고 해당 거래가 불가능하다고 단정하지 않는다.

```text
YES
가능

NO
불가능

CONDITIONAL
조건부 가능

NEGOTIABLE
협의 가능

UNKNOWN
정보 미등록
```

다만 바이어가 필수조건으로 지정한 항목이 UNKNOWN이면 자동 일치로 처리하지 않는다.

---

## 2.5 업체 주장과 검증정보 분리

업체가 직접 등록한 정보와 운영자가 검증한 정보를 동일한 신뢰도로 사용하지 않는다.

예시:

```text
업체 입력: 전국 유통 가능
검증자료: 미제출
상태: SELF_DECLARED
```

```text
업체 입력: 전국 유통 가능
계약서·납품실적 확인
상태: VERIFIED
```

---

## 7.2 거래조건 적용 단위

거래조건은 다음 세 수준으로 관리한다.

```text
업체 공통 거래조건
        ↓
제품별 거래조건
        ↓
바이어별 협의 거래조건
```

우선순위:

```text
바이어별 확정조건
> 제품별 조건
> 업체 공통조건
```

---

## 7.3 MOQ 구조

```json
{
  "min_order_quantity": 100,
  "quantity_unit": "BOTTLE",
  "package_unit": 12,
  "minimum_package_count": 10,
  "negotiable": true
}
```

MOQ를 단순 숫자 하나로 저장하지 않고 단위와 포장조건을 포함한다.

# 18. 거래 준비도

업체가 실제 상담과 거래를 수행할 준비가 되어 있는지를 평가한다.

## 18.1 거래 준비도 구성

```text
거래 준비도 =
거래조건 명확성       20%
생산·공급 가능성      20%
담당자·상담체계       15%
가격·MOQ 정보         15%
유통·배송 대응        10%
인증·증빙             10%
정보 최신성           10%
```

## 18.2 준비도 등급

| 등급                    | 의미          |
| --------------------- | ----------- |
| READY                 | 즉시 상담·거래 가능 |
| PARTIALLY_READY       | 일부 조건 확인 필요 |
| CONSULTATION_REQUIRED | 상담 후 판단     |
| NOT_READY             | 거래 추천 부적합   |
| UNKNOWN               | 정보 부족       |

거래 준비도는 업체의 우열 평가가 아니라, 바이어 상담을 진행할 수 있는 정보와 체계가 갖춰졌는지를 평가한다.

```text
5만 원 이하의 선물용 제품이며
현장에서 시음과 구매가 가능하다.
```

## 25.2 바이어용 문서

```text
A양조장은 서울·경기 지역 바틀샵에

최소주문수량은 100병이며
월 3,000병까지 공급할 수 있다.
OEM은 협의 가능하고 PB는 지원하지 않는다.
```

# 37. 제8단계 검수 기준

## 데이터 구조

* 업체·제품·거래조건·부스가 분리되어 있는가
* 상시정보와 행사정보가 분리되어 있는가
* 공개정보와 비공개 거래정보가 분리되어 있는가
* 제품별 거래조건을 저장할 수 있는가
* 업체 희망 바이어를 구조화할 수 있는가

## 매칭 활용

* 일반 관람객과 바이어가 서로 다른 공급 피처를 사용하는가
* MOQ·생산량·공급지역을 정량 비교할 수 있는가
* 미등록과 불가능 상태를 구분하는가
* 거래 준비도와 데이터 신뢰도를 점수에 반영할 수 있는가
* 부스 운영종료·품절을 실시간 반영할 수 있는가

## AI·검증

* AI 추출값과 업체 입력값이 분리되는가
* 근거문장과 신뢰도를 저장하는가
* 검증 전 거래정보를 필수조건으로 사용하지 않는가
* 업체 확인과 운영자 승인을 구분하는가
* 허위·과장 표현을 자동 확정하지 않는가

## 운영

* 업체 담당자가 직접 상태를 갱신할 수 있는가
* 가격·MOQ·생산량에 유효기간이 있는가
* 업체별 복수 담당자를 관리할 수 있는가
* 부스상태와 제품정보 충돌 시 우선순위가 있는가
* 과거 추천·상담 당시 버전을 재현할 수 있는가

# 38. 제8단계 확정사항

1. 업체·제품·거래조건·행사참가·부스 엔터티 분리
2. 상시 업체정보와 행사별 운영정보 분리
3. 공개정보·바이어정보·상담수락 후 정보의 공개범위 분리
4. 미등록·불가능·조건부·협의 가능 상태 구분
5. 제품별 맛·향·도수·가격·용도 프로파일 적용
6. MOQ·잔여 생산량·납기·공급지역 정량 관리
7. 업체 희망 바이어·채널·지역·거래규모 구조화
8. OEM·PB·독점유통·수출 조건 분리
9. 거래 준비도와 데이터 완성도 별도 산정
10. 업체 주장과 검증정보의 신뢰도 차등 적용
11. AI 속성추출 후 업체 확인·운영자 승인 절차 적용
12. B2C·B2B 검색문서와 임베딩 분리
