# 백주대간 AI 매칭서비스 재설계 체계 - 웹 초개인화 모듈·키오스크 검색모듈 분리안

> 이 문서는 사용자가 그대로 전달한 원문이다. `00-master-spec-v1.md`(통합 개발 명세서
> v1.0)의 실행 순서를 구체화한다 - "다음 단계부터 웹 모듈을 우선 설계"(§8-12)가 이후
> `docs/redesign-v2/web/`, `kiosk/`, `common/` 산출물의 순서를 정한다.

## 1. 재설계 기본방향

기존 설계를 다음 3개 영역으로 재구성한다.

```text
① 웹 초개인화 모듈
   사전등록 사용자·바이어 대상
② 키오스크 이식형 검색모듈
   현장 비등록 방문객 대상
③ 공통 AI·데이터 플랫폼
   두 채널이 공동으로 사용하는 기반
```

각 모듈의 사용자·화면·데이터·기능·배포방식을 독립적으로 설계하고, 공통으로 사용할 요소만 백엔드에서 공유한다.

## 2. 모듈별 핵심 정의

### 2.1 웹 초개인화 모듈

#### 대상

- 사전등록 일반 참가자
- 사전등록 바이어
- 회원 또는 인증 사용자

#### 핵심 기능

- 사전등록 데이터 연계
- 사용자 관심 프로파일 생성
- 관심분야 기반 업체·부스 추천
- 개인별 행사정보 전달
- 자연어 추가검색
- 관심 업체 저장
- 바이어·업체 매칭
- 간단 상담 요청
- 행사 전·중·후 정보 제공

#### 서비스 성격

```text
사용자를 알고 있는 상태
→ 먼저 맞춤정보를 제공하는 서비스
```

### 2.2 키오스크 이식형 검색모듈

#### 대상

- 현장 비등록 방문객
- 프로파일이 없는 게스트
- 빠르게 업체·부스를 찾는 이용자

#### 핵심 기능

- 다국어 시작화면
- 자연어 관심영역 검색
- 카테고리 검색
- 관련 업체·부스 목록
- 업체·제품 상세
- 부스 위치·지도
- QR 모바일 전송
- 자동 세션 초기화
- 행사별 설정 적용
- 기본 로컬 캐시

#### 서비스 성격

```text
사용자를 모르는 상태
→ 현재 질문을 이해해 관련 업체를 찾아주는 서비스
```

### 2.3 공통 AI·데이터 플랫폼

#### 공통 기능

- 업체·부스·제품 데이터 관리
- 관심분야 분류체계
- 자연어 의도·조건 추출
- 키워드·벡터 하이브리드 검색
- 업체·부스 랭킹
- 추천 이유 생성
- 업체정보 AI 구조화
- 행사별 데이터 관리
- 기본 통계·로그
- 관리자 권한·승인

#### 공통 사용 원칙

웹과 키오스크는 동일한 업체·부스 정보를 사용하지만 검색과 추천 방식은 분리한다.

```text
웹
사용자 프로파일 + 현재 요구 + 업체정보
키오스크
현재 질의 + 키오스크 위치 + 업체정보
```

## 4. 설계 진행순서

앞으로는 기존의 연속 30단계를 중단하고 다음 순서로 진행한다.

### A. 웹 초개인화 모듈 설계

- **W-1.** 서비스 범위·사용자 구분 - 사전등록 일반 참가자, 바이어, 참가업체, 운영자, 행사 전·중·후 제공범위
- **W-2.** 사용자 여정 - 사전등록 연계, 최초 로그인, 프로파일 확인, 추천 확인, 관심 저장, 행사 당일 활용, 행사 후 후속정보
- **W-3.** 사용자 화면 IA - 개인화 홈, 추천 업체·부스, 자연어 검색, 관심목록, 부스 상세, 바이어 매칭, MY 정보
- **W-4.** 프로파일 모델 - 등록정보, 관심분야, 방문목적, 바이어 거래조건, 사용자가 수정한 정보, 행사 내 제한적 행동정보
- **W-5.** 개인화 추천 로직 - 사용자·업체 적합도, 바이어·업체 적합도, 필수조건, 관련성 점수, 추천 이유
- **W-6.** 정보전달 정책 - 행사 전, 행사 당일, 행사 후, 알림함, 이메일·문자 연계, 수신동의
- **W-7.** 바이어 매칭·간단 상담 - 업체 추천, 업체 비교, 관심 저장, 상담 요청, 수락·거절, 연락처 공유
- **W-8.** 웹 API·DB - 사용자, 프로파일, 추천, 관심목록, 상담, 정보전달, 로그
- **W-9.** 관리자 운영 - 사전등록 연계, 업체정보 승인, 추천 대상 관리, 바이어 검증, 기본 통계
- **W-10.** 웹 검증·MVP 범위 - 사용자 시나리오, 추천 정확도, 사용성, 개인정보, 개발 우선순위

### B. 키오스크 이식모듈 설계

- **K-1.** 키오스크 서비스 범위 - 익명 이용, 비회원, 현장 검색, 세션 종료, 모바일 연결
- **K-2.** 키오스크 사용자 흐름 - 시작, 언어 선택, 관심분야 선택, 자연어 검색, 결과 확인, 지도, QR 전송, 초기화
- **K-3.** 키오스크 화면 IA - 대기화면, 검색화면, 카테고리화면, 결과목록, 업체상세, 지도, QR화면, 오류화면
- **K-4.** 자연어 검색 로직 - 관심영역 추출, 업체·제품·부스 검색, 검색결과 랭킹, 결과 없음 처리, 최소 추가질문
- **K-5.** 지도·위치·QR 연결 - 키오스크 설치위치, 부스 위치, 경로 표시, QR 세션 전달, 모바일 게스트 웹
- **K-6.** 다국어·접근성 - 지원언어, 쉬운 문장, 큰 글자, 터치영역, 음성입력 선택, 고유명사 처리
- **K-7.** 이식형 패키지 구조 - 행사별 설정, 테마·로고, 지도파일, API 주소, 언어팩, 자동 업데이트, 로컬 캐시
- **K-8.** 키오스크 검증·MVP 범위 - 검색 성공률, 응답시간, 세션 초기화, 개인정보 잔존, 현장 사용성, 장애대응

### C. 공통 AI·데이터 플랫폼 설계

- **C-1.** 업체·부스 데이터 모델 - 업체, 제품·서비스, 부스, 관심분야 코드, 공개 거래정보, 행사 참가정보
- **C-2.** 업체정보 수집·AI 구조화 - 참가신청서, 업체소개, 제품자료, AI 추출, 업체 확인, 운영자 승인
- **C-3.** 관심분야 온톨로지 - 산업, 기술, 제품·서비스, 활용목적, 바이어 거래유형, 유사어·다국어
- **C-4.** 검색·추천 공통엔진 - 구조화 검색, 키워드 검색, 벡터 검색, Hard Filter, 관련성 랭킹, 추천 이유
- **C-5.** 공통 API - 업체검색, 업체상세, 부스검색, 추천, 자연어 질의, QR 세션, 관리자 승인
- **C-6.** 개인정보·권한 - 웹 사용자 동의, 키오스크 무수집, 바이어 정보공개, 업체 공개범위, 로그·감사
- **C-7.** 공통 인프라 - 웹·키오스크 API, DB, 캐시, 벡터검색, 파일저장, 모니터링
- **C-8.** 통합시험·배포 - 웹·키오스크 데이터 일치, 검색결과 일치, 행사별 설정, 운영배포, 로그·통계

## 5. 설계 범위에서 제외할 내용

다음 기능은 현재 MVP 설계에서 제외하고 확장항목으로 이동한다.

- 정밀 사용자 위치추적
- 복잡한 방문경로 최적화
- 실시간 혼잡 추정모델
- 제품별 실시간 재고관리
- 장기 거래 CRM
- 견적·계약·정산
- 샘플 배송관리
- 대규모 상담장 자동배정
- 실시간 온라인 학습형 랭킹
- 복잡한 공정성 최적화
- 독립 마케팅 자동화 플랫폼
- 키오스크 회원가입
- 키오스크 장기 프로파일
- 키오스크 개인정보 입력

## 6. 기존 설계 활용방식

기존 제1~28단계는 다음과 같이 처리한다.

| 기존 설계 | 처리 |
| --- | --- |
| 사용자 유형·여정 | 웹 모듈에 재사용 |
| 화면 IA | 웹·키오스크로 재분리 |
| 업체·제품 DB | 공통 플랫폼에 재사용 |
| 자연어 프로파일링 | 웹용으로 축소 |
| 자연어 검색 | 키오스크 핵심으로 이동 |
| B2C·B2B 점수 | 웹 모듈에 재사용 |
| 콜드스타트 | 키오스크 검색으로 단순화 |
| 행동학습 | 웹 등록 사용자만 제한 적용 |
| RAG·벡터검색 | 공통 검색엔진으로 재사용 |
| 상담 CRM | 간단 상담 요청만 유지 |
| 현장 관제·재고 | 기본 부스 상태만 유지 |
| 오프라인 PWA | 키오스크 로컬 캐시 수준으로 축소 |
| MLOps·DR | MVP 필요수준으로 축소 |

## 7. 새로운 진행 기준

앞으로 단계는 다음 순서로 진행한다.

```text
1차: 웹 초개인화 모듈 W-1~W-10
2차: 키오스크 이식모듈 K-1~K-8
3차: 공통 AI·데이터 플랫폼 C-1~C-8
4차: 통합 아키텍처·개발 로드맵
```

먼저 **W-1 웹 초개인화 모듈의 서비스 범위와 사용자 구분**부터 다시 시작한다.

## 8. 이번 재설계 확정사항

1. 웹과 키오스크를 별도 서비스 모듈로 분리
2. 웹은 사전등록 사용자 초개인화 중심
3. 키오스크는 현장 비등록 방문객 자연어 검색 중심
4. 현장 게스트에게 지속 프로파일을 생성하지 않음
5. 키오스크는 회원가입·연락처·장기행동정보를 수집하지 않음
6. 두 모듈은 공통 업체·부스 DB와 검색엔진을 공유
7. 바이어 매칭은 웹의 독립 흐름으로 유지
8. 상담은 요청·수락 수준의 간단 기능만 MVP에 포함
9. 계약·견적·장기 CRM은 2차 확장으로 이동
10. 현장 혼잡·재고·정밀경로 기능은 기본범위에서 제외
11. 기존 설계 결과는 모듈별 참고자료로 재분류
12. 다음 단계부터 웹 모듈을 우선 설계
