# K-7. 키오스크 이식형 검색모듈 - 이식형 패키지 구조

근거 문서: `docs/redesign-v2/00-master-spec-v1.md`(§45.2, §56), `docs/redesign-v2/01-module-split-plan.md`(§4-B K-7, §6 "오프라인 PWA → 키오스크 로컬 캐시 수준으로 축소"). "이식형"이라는 이름 자체가 의미하는 바 - 동일 소프트웨어를 여러 행사에 반복 배포할 수 있어야 한다는 요구를 구체화한다.

## 1. 행사별 설정 (단일 설정 파일)

키오스크 앱은 행사마다 다시 빌드하지 않고, 다음 항목을 담은 설정 파일 하나만 교체해 재배포한다.

```text
kiosk-config.json
  event_id
  zone_id           (K-5 §1의 "키오스크 설치위치" 고정값)
  api_base_url      (§4)
  supported_languages  (K-6 §1)
  theme             (§2)
  map_asset_ref     (§3)
```

## 2. 테마·로고

- 행사 주최측 브랜딩(로고·색상)을 설정 파일의 `theme` 필드로 주입 - 코드 변경 없이 CSS 변수/이미지 경로 교체만으로 처리한다.

## 3. 지도파일

- 행사장 지도는 [K-5 §2](K-5-map-location-qr.md)의 "구역 단위" 표시 원칙에 따라 정밀 좌표 지도가 아니라 **구역 배치도(정적 이미지 + zone 하이라이트 오버레이)** 수준으로 충분하다 - 이는 §56의 "정밀 위치추적" 제외 원칙과 직접 연결된다. 지도파일 자체를 행사마다 교체 가능한 정적 자산으로 패키지에 포함한다.

## 4. API 주소

- `api_base_url`은 공통 플랫폼(C-5 공통 API)의 엔드포인트를 가리킨다 - 키오스크는 이 값 하나만 바꾸면 다른 백엔드 환경(스테이징/운영)이나 향후 멀티 테넌트 배포 시 다른 테넌트로도 재배포 가능하다.

## 5. 언어팩

- [K-6 §1](K-6-i18n-accessibility.md)에서 확정한 `supported_languages` 목록에 대응하는 번역 문자열 파일 - 설정 파일과 함께 교체 가능한 정적 자산.

## 6. 자동 업데이트

- 마스터 스펙 §56의 "복잡한 MLOps" 제외 원칙에 따라, 정교한 무중단 배포 파이프라인은 만들지 않는다. **MVP 범위: 앱 시작 시(대기화면 진입 전) 설정 파일·지도·언어팩의 최신 버전을 서버에서 확인하고, 변경 있으면 내려받아 교체 후 재시작하는 수준**으로 한정한다 - 세션 도중 업데이트는 하지 않는다(세션 중간에 자산이 바뀌면 사용자 경험이 깨지므로).

## 7. 기본 로컬 캐시

- [K-3 §2](K-3-screen-ia.md)의 "네트워크 단절" 오류화면에서 참조한 캐시 - 마지막으로 성공한 검색 결과(인기 카테고리별 상위 N개)만 로컬에 캐시하고, 네트워크 복구 전까지는 "실시간 검색은 어렵지만 인기 업체는 볼 수 있다"는 제한된 기능으로 폴백한다.
- 01-module-split-plan.md §6이 "오프라인 PWA → 키오스크 로컬 캐시 수준으로 축소"라 명시한 대로, 오프라인에서 완전한 검색 기능을 제공하는 PWA를 만들지 않는다 - 캐시는 순수 폴백 수단이다.
- **개인정보 관점**: 캐시에 저장하는 것은 "업체·카테고리 목록"(공개 데이터)뿐이며 사용자별 검색 이력은 캐시하지 않는다 - [K-1 §4](K-1-service-scope.md)의 "개인정보 잔존 없음" 원칙과 충돌하지 않는다.
