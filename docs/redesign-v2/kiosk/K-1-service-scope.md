# K-1. 키오스크 이식형 검색모듈 - 서비스 범위

근거 문서: `docs/redesign-v2/00-master-spec-v1.md`(§1, §23, §45.2, §56), `docs/redesign-v2/01-module-split-plan.md`(§4-B K-1). 웹 모듈 설계([W-1](../web/W-1-scope-and-user-types.md) §1)에서 "`KIOSK_GUEST`는 웹 모듈 범위 밖"이라 확정한 것을 여기서 본격적으로 다룬다.

## 0. 뜻밖의 좋은 소식: 기존 스키마가 이미 3분할을 예견하고 있었다

`backend/app/models/identity.py`의 `GuestSession.entry_channel`은 이미 `IN ('QR', 'WEB', 'KIOSK')`로 정의돼 있다 - 즉 이번 재설계 이전부터 "키오스크 자체 이용"과 "키오스크에서 QR로 넘어온 웹 이용"과 "웹에서 바로 온 익명 이용"을 서로 다른 채널로 구분해 왔다. 이는 마스터 스펙의 웹/키오스크 분리 원칙과 우연히 정확히 일치한다 - 재설계라기보다 기존 설계 의도를 재발견한 것에 가깝다.

| entry_channel | 대응 사용자([W-1](../web/W-1-scope-and-user-types.md) 분류) | 세션이 사는 곳 |
| --- | --- | --- |
| `KIOSK` | `KIOSK_GUEST` | 키오스크 디바이스(오프라인 우선, K-7) |
| `QR` | `GUEST_WEB`(키오스크에서 인계) | 모바일 웹 |
| `WEB` | `GUEST_WEB`(웹에서 직접 방문) | 웹 |

## 1. 익명 이용 원칙

- `KIOSK_GUEST`는 `profile.GuestSession` 행조차 개인 식별 정보를 담지 않는다 - 스키마상 `session_token_hmac`(원문 토큰 미저장), `device_type`, `language`만 있고 이름·연락처 컬럼이 아예 없다. 즉 "회원가입을 안 만든다"가 아니라 **테이블 구조 자체에 개인정보를 넣을 자리가 없다.**
- **결정**: `KIOSK_GUEST`에는 `profile.UserProfile` 행을 생성하지 않는다. [W-1 §3](../web/W-1-scope-and-user-types.md)에서 `GUEST_WEB`은 `UserProfile`(소유자 `guest_session_id`)을 갖는다고 했지만, 순수 키오스크 이용(QR 인계 이전)은 그 단계에 도달하기 전이므로 프로파일 자체가 필요 없다 - 검색은 무프로파일 검색(현재 질의 + 위치만)이기 때문이다(01-module-split-plan.md §2.3).

## 2. 비회원 검색 - "무엇을 모르는 상태에서 무엇을 아는 상태로"

- 키오스크는 사용자를 전혀 모른다(01-module-split-plan.md §2.2 "사용자를 모르는 상태"). 유일한 입력은 (a) 현재 자연어 질의, (b) 키오스크 설치 위치(zone), (c) 언어 선택이다.
- **기존 스키마 재사용 여부**: `profile.ContextProfile`(현재 zone, 잔여시간 등)은 `visit_session_id`에 종속되는데, 키오스크 이용은 `visit_session`을 만들지 않는다(방문세션은 웹 모듈의 "행사 당일 활용" 개념, [W-2 §1-8](../web/W-2-user-journey.md)). **키오스크의 "현재 위치"는 `ContextProfile`이 아니라 키오스크 디바이스 자체의 설치 위치 메타데이터**(K-7에서 정의)로 처리한다 - 검색할 때마다 세션에 위치를 새로 묻는 것이 아니라, 디바이스 설정에 고정된 값이기 때문이다.

## 3. 현장 검색

- 검색 엔진 자체(자연어 의도 추출, 키워드·벡터 하이브리드 검색, 랭킹)는 공통 플랫폼(C-4)이 담당 - K 시리즈는 "그 엔진을 키오스크 UX로 어떻게 소비하는가"만 다룬다(K-4에서 상세화).

## 4. 세션 종료 (자동 초기화)

- `GuestSession.expires_at`이 이미 존재하므로, 키오스크 세션은 이 컬럼을 짧은 TTL(예: 이용 종료 후 수십 초~수 분, 정확한 값은 K-8 검증에서 확정)로 설정하고 만료 시 클라이언트가 즉시 초기 화면으로 리셋한다.
- **마스터 스펙 §45.2 "키오스크 개인정보 잔존 없음" 요구**: `KIOSK_GUEST`는 애초에 `UserProfile`을 만들지 않으므로(§1) "잔존할 개인정보"가 서버 측에는 없다. 클라이언트(키오스크 디바이스) 측 잔존은 K-7(로컬 캐시)에서 별도로 다룬다 - 화면 전환 시 이전 세션의 검색어·결과가 메모리/DOM에 남지 않도록 하는 것은 프론트엔드 구현 사항.

## 5. 모바일 연결 (QR 전송)

- QR 스캔 시 `GuestSession`을 새로 만들지 않고 **`entry_channel='KIOSK'`인 기존 세션의 검색 결과를 `entry_channel='QR'`인 새 세션으로 "인계"**하는 방식을 취한다 - 두 세션을 동일 레코드로 이어붙이지 않는 이유는, 키오스크 세션과 모바일 세션은 서로 다른 디바이스·다른 `session_token_hmac`을 가져야 하기 때문이다(디바이스 간 세션 공유는 보안상 별도 토큰이 필요).
- 인계되는 데이터는 "마지막 검색 결과 목록"뿐이다 - 검색 질의 자체나 그 이전 상호작용은 인계하지 않는다([W-2 §3](../web/W-2-user-journey.md)와 일치: GUEST_WEB은 "인계받은 결과 열람"만 하고 새 검색은 하지 않는 것이 기본값).
- QR 인계 메커니즘의 구체적 프로토콜(단기 토큰 발급 방식 등)은 K-5(지도·위치·QR 연결)에서 상세화한다.

## 6. K-1에서 확정하는 K 시리즈 전체 제외사항

01-module-split-plan.md §5의 "키오스크 회원가입, 키오스크 장기 프로파일, 키오스크 개인정보 입력" 3개는 K 시리즈 전체에 걸쳐 절대 원칙으로 취급한다 - 이후 K-2~K-8의 어떤 화면·API 설계도 이 3개를 위반하지 않는지 K-8(검증)에서 최종 확인한다.

## 7. K-2로 넘기는 질문

1. 언어 선택이 세션 시작 전(초기 화면)인지, 세션 시작과 동시에 브라우저/디바이스 로케일로 자동 결정되는지 - K-2(사용자 흐름)에서 순서를 확정한다.
