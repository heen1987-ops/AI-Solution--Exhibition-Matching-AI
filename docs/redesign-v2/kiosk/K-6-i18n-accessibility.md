# K-6. 키오스크 이식형 검색모듈 - 다국어·접근성

근거 문서: `docs/redesign-v2/00-master-spec-v1.md`(§23), `docs/redesign-v2/01-module-split-plan.md`(§4-B K-6). [K-2 §7](K-2-user-flow.md)(음성입력 기본제공 여부)을 확정한다.

## 1. 지원언어

- `GuestSession.language`(기존 컬럼) 값 목록을 서비스 정책으로 확정: 한국어(`ko-KR`, 기본값) + 최소 영어(`en-US`) - 행사 성격(외국 바이어 참여 여부)에 따라 K-7(행사별 설정)에서 언어팩을 추가/제거할 수 있는 구조로 둔다. 특정 언어 개수를 하드코딩하지 않는다.

## 2. 쉬운 문장·큰 글자·터치영역

- 이 3가지는 순수 프론트엔드 구현 가이드라인이며 백엔드 스키마·API에 영향이 없다 - 이번 문서에서는 "지켜야 할 제약"만 명시하고 구체적 수치(폰트 크기 px 등)는 UI 구현 단계에서 디자인 시스템으로 정한다.
- 원칙: 한 화면에 한 가지 결정만 요구한다(카테고리 선택 화면에 검색 입력창을 동시에 노출하지 않는 등) - [K-3](K-3-screen-ia.md)의 화면 분리가 이미 이 원칙을 따르고 있다.

## 3. 음성입력 - 기본 제공 여부 결정

[K-2 §7](K-2-user-flow.md)에서 넘긴 질문. **결정: MVP 기본값은 텍스트 입력만 제공하고, 음성입력은 확장 항목으로 분류한다.**

이유: 마스터 스펙 §56 제외목록에 음성입력이 명시적으로 언급되지는 않지만, 다국어 음성인식은 언어별 인식 엔진 연동·소음 환경(전시장 현장) 정확도 문제 등 구현 복잡도가 높아 "복잡한 MLOps"에 준하는 비용이 든다. [K-3 §7](K-3-screen-ia.md)에서 이미 화면 슬롯은 예비해뒀으므로, 향후 확장 시 K-3 화면 구조를 바꾸지 않고 입력 방식만 추가할 수 있다.

## 4. 고유명사 처리

- 업체명·제품명 등 고유명사는 다국어 번역 대상이 아니라 원문 그대로 표기하는 것을 원칙으로 한다(오역 위험) - 카테고리·안내 문구만 번역 대상이다.
- **확인 완료**: `backend/app/models/exhibitor.py`의 `Exhibitor.company_name`은 `String(200)` 단일 컬럼이며 언어별 변형 컬럼이 없다 - 즉 고유명사 원문 단일 표기 원칙이 스키마 현실과 이미 일치한다. 다국어 명칭 컬럼을 신설할 필요가 없다.
