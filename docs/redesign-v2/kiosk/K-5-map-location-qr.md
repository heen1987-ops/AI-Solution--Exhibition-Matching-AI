# K-5. 키오스크 이식형 검색모듈 - 지도·위치·QR 연결

근거 문서: `docs/redesign-v2/00-master-spec-v1.md`(§23), `docs/redesign-v2/01-module-split-plan.md`(§4-B K-5, §56 제외목록). [K-1 §5](K-1-service-scope.md)에서 예고한 QR 인계 프로토콜을 상세화한다.

## 1. 키오스크 설치위치

- 키오스크 디바이스는 설치 시점에 고정된 `event_zone_id`(기존 `exhibition.event_zone` 참조)를 설정으로 갖는다 - 세션마다 위치를 다시 묻지 않는다([K-1 §2](K-1-service-scope.md) "디바이스 설정에 고정된 값"). 이 값은 K-7(이식형 패키지 구조)의 "행사별 설정" 항목의 일부로 관리한다.

## 2. 부스 위치·경로 표시

- 부스 위치는 `exhibition.booth`(기존 스키마)의 zone 소속 정보를 그대로 사용 - 좌표가 아니라 구역 단위([W-2 §1-8](../web/W-2-user-journey.md)에서 웹 모듈도 동일 원칙을 확인함).
- **경로 표시의 범위**: 마스터 스펙 §56의 "복잡한 방문경로 최적화" 제외 원칙에 따라, "키오스크 현재 위치 zone → 목적지 zone"의 단순 방향 안내(지도 위 하이라이트) 수준까지만 제공한다 - 여러 부스를 들르는 최적 동선 계산은 하지 않는다.

## 3. QR 세션 전달 프로토콜

[K-1 §5](K-1-service-scope.md)에서 "두 세션을 동일 레코드로 이어붙이지 않는다"고 확정한 것을 구체적 절차로 정의한다.

```text
1. 키오스크 세션(entry_channel=KIOSK)이 결과 목록을 표시 중인 상태에서 QR 버튼 클릭
2. 서버가 단기 인계 토큰(예: 5분 TTL, 1회용) 발급
   - 인계 토큰이 참조하는 데이터: 마지막 결과 목록의 ID 집합 + language
   - 이 토큰은 GuestSession과 별개의 단기 레코드(신규 테이블 필요 여부는 §5 참고)
3. 모바일이 QR을 스캔 → 인계 토큰으로 웹 접속
4. 서버가 새 GuestSession(entry_channel=QR) 생성, 인계된 결과 목록을 그 세션에 연결
5. 키오스크 쪽 세션은 즉시 종료 처리([K-2 §5](K-2-user-flow.md))
```

- **1회용 원칙**: 인계 토큰은 스캔 성공 시 즉시 폐기한다 - QR 코드를 촬영해뒀다가 나중에 재사용하는 것을 막기 위함(§56에 명시되진 않았으나 일반적 보안 원칙으로 채택).

## 4. 모바일 게스트 웹 - 웹 모듈과의 경계 재확인

- QR 인계 이후 화면은 웹 모듈의 S-2(추천 업체·부스 목록, [W-3](../web/W-3-screen-ia.md))를 그대로 사용한다 - **K 시리즈가 별도의 "키오스크 전용 모바일 웹 화면"을 만들지 않는다.** [W-3 §0](../web/W-3-screen-ia.md)에서 이미 GUEST_WEB이 S-2에 "제한적 접근(△)"으로 표시된 것이 바로 이 인계 결과 화면이다.

## 5. 인계 토큰 저장 위치 - 결정

**결정: 신규 테이블을 만들지 않고, `GuestSession.entry_code`(기존 컬럼)를 인계 토큰 값으로 사용한다.** `entry_code`는 이미 "QR/초대코드 등 진입 경로 식별자"라는 의도로 존재하는 nullable 컬럼이며, 새 `GuestSession(entry_channel='QR')` 레코드를 생성하면서 이 컬럼에 키오스크 세션에서 받은 인계 토큰 값을 채우고, 그 값으로 "인계된 결과 목록"을 조회하는 조인 키로 쓰면 별도 테이블 없이 §3의 흐름을 구현할 수 있다. "마지막 결과 목록"은 키오스크 세션 자체(`entry_channel='KIOSK'`인 `GuestSession`)의 검색 로그에서 조회하므로, 결과 목록을 별도로 복제 저장할 필요도 없다.
