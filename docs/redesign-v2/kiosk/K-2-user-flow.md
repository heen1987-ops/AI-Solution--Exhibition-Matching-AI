# K-2. 키오스크 이식형 검색모듈 - 사용자 흐름

근거 문서: `docs/redesign-v2/00-master-spec-v1.md`(§23), `docs/redesign-v2/01-module-split-plan.md`(§4-B K-2). [K-1 §7](K-1-service-scope.md)의 미결정 사항(언어 선택 시점)을 확정하고 전체 흐름을 정의한다.

## 1. 전체 흐름

```text
1. 대기화면(다국어 안내 순환 표시)
2. 터치 → 언어 선택
3. 관심분야 선택(카테고리 버튼) 또는 자연어 검색 입력 중 선택
4a. [카테고리] 관심분야 선택 → 결과 목록
4b. [자연어] 텍스트/음성 입력 → 결과 목록
5. 결과 목록 → 업체 상세
6. 지도에서 부스 위치 확인
7. QR 코드 표시 → 모바일 스캔 → 웹으로 인계
8. (시간 경과 또는 완료 버튼) → 자동 세션 초기화 → 1번으로 복귀
```

## 2. 언어 선택 시점 - 확정

**결정: 세션 시작 전, 대기화면에서 명시적으로 선택한다.** 디바이스 로케일 자동 감지에 의존하지 않는다.

이유: 키오스크는 여러 언어권 방문객이 같은 물리 디바이스를 순서대로 사용하는 공유 단말이다 - 디바이스 로케일은 고정값이라 이전 사용자가 선택한 언어가 다음 사용자에게 그대로 남는 문제가 생긴다. `GuestSession.language`(기존 컬럼, 기본값 `ko-KR`)는 세션 단위 값이므로, 매 세션 시작 시 사용자가 명시적으로 고른 값으로 이 컬럼을 채우는 것이 원칙과 스키마 양쪽에 부합한다.

## 3. 관심분야 선택 vs 자연어 검색 - 진입점 분기

- 두 경로 모두 최종적으로 동일한 "결과 목록" 화면(K-3의 결과목록 화면)으로 수렴한다 - 카테고리 선택은 내부적으로 "그 카테고리 개념(concept)을 조건으로 한 자연어 검색"과 동일하게 처리되어, 검색 엔진(C-4) 호출 방식이 하나로 통일된다. 별도의 "카테고리 전용 검색 로직"을 만들지 않는다.
- 이는 01-module-split-plan.md §2.2의 핵심 기능 목록("자연어 관심영역 검색"과 "카테고리 검색"이 나란히 나열된 것)을 "두 개의 서로 다른 검색 엔진"이 아니라 "검색 엔진에 대한 두 개의 서로 다른 입력 방식"으로 해석한 것이다.

## 4. 최소 추가질문 (K-4 예고)

- 자연어 검색 결과가 모호하거나(예: 너무 광범위) 결과가 없을 때, 마스터 스펙 §23은 "최소 추가질문"을 허용한다 - 단, 이는 다단계 대화형 챗봇이 아니라 **최대 1회, 선택지 형태의 단일 질문**으로 한정한다(§56 "복잡한 공정성 최적화"·"대규모 온라인 학습" 제외 원칙과 같은 맥락 - 검색을 대화로 확장하지 않는다). 상세 로직은 K-4에서 다룬다.

## 5. QR 전송 이후 - 세션 상태

- QR 스캔이 완료되면(모바일 쪽에서 인계 세션이 생성되면) 키오스크 쪽 세션은 즉시 완료 처리하고 초기화 카운트다운을 시작한다 - QR 스캔 이후에도 키오스크 화면에서 계속 조작 가능하게 두면 다음 사용자와의 세션 경계가 모호해지므로, "QR 표시 = 이 세션의 사실상 마지막 단계"로 취급한다.

## 6. 자동 세션 초기화 트리거

3가지 트리거를 모두 지원한다: (a) 완료 버튼 명시적 클릭, (b) QR 스캔 완료, (c) 무입력 타임아웃. 정확한 타임아웃 값은 K-8(현장 사용성 검증)에서 확정 - 이 문서에서는 트리거 종류만 정의한다.

## 7. K-3으로 넘기는 질문

1. 자연어 검색 입력을 텍스트만 지원할지 음성입력도 기본 제공할지 - K-6(다국어·접근성)에서 확정하되, K-3(화면 IA)은 두 입력 방식 모두를 화면 슬롯으로 예비해 둔다.
