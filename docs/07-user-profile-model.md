# 1. 단계 목적

본 단계의 목적은 일반 관람객과 바이어의 방문목적, 취향, 거래조건, 현장 행동, 현재 상황을 통합하여 **추천 시점별로 활용 가능한 동적 사용자 프로파일 모델**을 정의하는 데 있다.

사용자 프로파일은 단순 회원정보나 설문 응답이 아니라 다음 정보를 결합한 추천용 데이터 자산으로 구성한다.

* 사용자가 직접 입력한 정보
* 사용자가 선택·수정한 선호조건
* 조회·저장·방문·상담 등 행동정보
* 행사 당일 위치·시간·일정 등 상황정보
* 자연어에서 추출한 잠재 요구조건
* 정보별 신뢰도·최신성·적용기간
* 추천과 피드백에 따른 프로파일 변화이력

---

# 2. 프로파일 설계 원칙

## 2.1 식별정보와 추천정보 분리

성명, 전화번호, 이메일 등 직접 식별정보는 추천 프로파일에서 분리한다.

```text
[사용자 식별영역]
성명·전화번호·이메일·인증정보
           │ user_id
           ▼
[추천 프로파일 영역]
방문목적·취향·가격·거래조건·행동특성
```

추천엔진은 원칙적으로 이름, 연락처, 이메일을 사용하지 않는다.

---

## 2.2 직접 입력 우선

프로파일 값의 우선순위는 다음과 같이 적용한다.

```text
사용자 직접 입력·수정
> 최근 명시적 피드백
> 반복 행동에 의한 추론
> 자연어 AI 추출
> 기본값·유사 사용자 통계
```

사용자의 명시적 선택과 행동추론이 충돌하는 경우 직접 입력값을 우선한다.

---

## 2.3 고정정보와 가변정보 분리

| 구분       | 예시              | 변경주기  |
| -------- | --------------- | ----- |
| 상대적 고정정보 | 사용자 유형, 조직 유형   | 낮음    |
| 중기 선호정보  | 선호 주종, 맛, 거래채널  | 중간    |
| 방문별 정보   | 오늘의 방문목적, 체류시간  | 높음    |
| 실시간 상황정보 | 현재 위치, 혼잡, 남은시간 | 매우 높음 |
| 행동추론 정보  | 최근 관심 제품, 가격 반응 | 지속 변경 |

---

## 2.4 미입력과 비선호 구분

사용자가 선택하지 않은 항목을 비선호로 처리하지 않는다.

```text
UNKNOWN
정보 없음

NEUTRAL
특별한 선호 없음

PREFERRED
선호

REQUIRED
필수

EXCLUDED
제외
```

'미입력'과 '싫어함'을 같은 값으로 다루면 추천 후보를 불필요하게 제거하게 된다.

---

## 2.5 시간과 상황에 따른 가변성 반영

사용자의 평소 선호와 이번 방문 목적은 다를 수 있다.

예시:

```text
평소 선호: 저도주·달콤한 술
이번 방문: 부모님 선물용 프리미엄 증류주 탐색
```

추천 시에는 이번 방문 목적을 우선 적용하고, 장기 선호는 보조정보로 활용한다.

# 4. 프로파일 계층

## 4.1 계정 프로파일

행사와 무관하게 사용자 계정에 귀속되는 기본 프로파일이다.

### 주요 속성

* 사용자 계정 유형
* 기본 언어
* 기본 시간대
* 본인인증 상태
* 바이어 인증 상태
* 소속기관 검증 상태
* 접근성 기본설정
* 개인화 동의 상태

계정 프로파일은 추천에 직접 사용하는 정보보다 권한·인증·기본환경 설정에 활용한다.

---

## 4.2 행사 프로파일

특정 행사에 대한 사용자의 목적과 선호를 저장한다.

### 주요 속성

* 행사별 사용자 유형
* 방문목적
* 관심 제품군
* 가격범위
* 시음·구매 선호
* 바이어 거래조건
* 상담 희망주제
* 관심 지역·업체 유형

행사마다 별도의 프로파일을 생성한다.

---

## 4.3 방문 세션 프로파일

특정 날짜와 방문 세션에만 적용되는 프로파일이다.

### 주요 속성

* 방문일
* 입장시간
* 예상 체류시간
* 현재 위치
* 이동 선호
* 오늘 방문한 부스
* 오늘 제외한 추천
* 오늘의 고정 상담일정
* 이번 방문의 최우선 목표

---

## 4.4 추천 세션 스냅샷

추천이 생성된 순간의 전체 프로파일을 변경 불가능한 형태로 저장한다.

```text
행사 프로파일
+ 방문 세션 프로파일
+ 행동추론 프로파일
+ 현재 상황정보
= 추천 프로파일 스냅샷
```

과거 추천 결과를 재현하기 위해 반드시 저장한다.

---

# 5. 사용자 유형별 프로파일

## 5.1 일반 관람객 프로파일

| 영역   | 주요 항목                 |
| ---- | --------------------- |
| 방문목적 | 시음, 구매, 선물, 체험, 정보탐색  |
| 제품선호 | 주종, 맛, 향, 도수, 원료      |
| 구매조건 | 가격, 구매수량, 현장구매, 배송    |
| 이용조건 | 체류시간, 이동거리, 혼잡 회피     |
| 경험선호 | 시음, 프로그램, 양조장 이야기     |
| 행동정보 | 조회, 저장, QR 방문, 구매 피드백 |

---

## 5.2 바이어 프로파일

| 영역   | 주요 항목                |
| ---- | -------------------- |
| 조직정보 | 조직 유형, 업종, 담당업무      |
| 유통채널 | 바틀샵, 온라인몰, 호텔, 수출 등  |
| 제품수요 | 주종, 가격, 원료, 차별성      |
| 거래조건 | MOQ, 월 주문량, 공급지역     |
| 협력유형 | 유통, OEM, PB, 독점, 수출  |
| 의사결정 | 도입시점, 예산, 의사결정 권한    |
| 상담조건 | 희망주제, 가능시간, 담당자      |
| 행동정보 | 업체조회, 비교, 상담요청, 후속조치 |

---

## 5.3 복수 역할 프로파일

한 사용자는 일반 관람객과 바이어 역할을 동시에 가질 수 있다.

예시:

```text
사용자 A
├─ 일반 관람객 프로파일
│  └─ 개인 구매·시음 목적
└─ 바이어 프로파일
   └─ 회사 유통·입점 목적
```

추천 요청 시 적용 역할을 선택하거나 화면 흐름에 따라 자동 분기한다.

복수 역할의 속성을 하나로 합치지 않는다.

---

# 6. 명시적 프로파일

명시적 프로파일은 사용자가 직접 입력하거나 선택한 정보이다.

## 6.1 주요 명시적 속성

### 일반 관람객

* 방문목적
* 선호 주종
* 선호 맛·향
* 선호 도수
* 가격범위
* 구매의향
* 선물 여부
* 시음·체험 선호
* 이동·혼잡 선호

### 바이어

* 조직·유통채널
* 희망 제품군
* 목표 가격
* 예상 주문량
* 공급 희망지역
* OEM·PB 요구
* 수출 희망국
* 거래 희망시기
* 상담주제

---

## 6.2 명시적 속성 구조

```json
{
  "attribute_code": "TASTE.DRY",
  "value": 4,
  "requirement_level": "PREFERRED",
  "priority": 2,
  "source": "USER_SELECTED",
  "confidence": 1.0,
  "valid_from": "2026-10-09T00:00:00+09:00",
  "valid_until": null
}
```

---

## 6.3 우선순위

사용자가 복수 조건을 선택한 경우 우선순위를 관리한다.

```text
1순위: 부모님 선물용
2순위: 5만 원 이하
3순위: 드라이한 증류주
```

점수 계산 시 동일 가중치로 처리하지 않고 목적 우선순위를 반영한다.

---

# 7. 암묵적 행동 프로파일

암묵적 프로파일은 사용자의 행동에서 추론한 선호와 의도를 저장한다.

## 7.1 행동 강도

| 행동      | 기본 의미   | 신호 강도 |
| ------- | ------- | ----: |
| 추천 노출   | 단순 노출   |     0 |
| 상세조회    | 약한 관심   |     1 |
| 장시간 조회  | 관심      |     2 |
| 비교 추가   | 높은 관심   |     3 |
| 관심 저장   | 높은 관심   |     4 |
| 경로 추가   | 방문 의도   |     5 |
| QR 체크인  | 실제 방문   |     6 |
| 시음      | 제품 경험   |     7 |
| 구매      | 강한 긍정행동 |     9 |
| 상담 요청   | 강한 거래의도 |     9 |
| 상담 완료   | 실질 거래행동 |    10 |
| 추천 제외   | 부정 신호   |    -4 |
| 부적합 피드백 | 강한 부정   |    -8 |

행동 가중치는 제17단계에서 검증·보정한다.

---

## 7.2 행동에서 추론 가능한 속성

### 제품 관심

* 반복 조회한 주종
* 저장한 가격대
* 방문한 원료·지역
* 시음한 맛 속성
* 구매한 제품 특성

### 이용행태

* 가까운 부스를 선호하는지
* 혼잡한 부스를 회피하는지
* 제품 상세를 오래 보는지
* 프로그램보다 구매를 선호하는지
* 계획형인지 즉흥형인지

### 바이어 의도

* 자주 조회한 유통조건
* 비교한 업체 수
* MOQ 조건 반응
* 상담요청 주제
* 후속조치 여부

---

# 8. 행동 기반 추론 규칙

## 8.1 단일 행동 과대해석 방지

한 번의 클릭이나 방문만으로 강한 선호를 확정하지 않는다.

```text
1회 조회
→ 임시 관심

반복 조회
+ 관심 저장
+ 실제 방문
→ 유효 선호 추정
```

---

## 8.2 긍정·부정 행동 분리

추천 제외가 곧 해당 제품군 전체에 대한 비선호를 의미하지 않는다.

예시:

```text
추천 제외 사유: 혼잡
→ 부스 상황 감점
→ 제품 취향 감점 금지
```

```text
추천 제외 사유: 가격이 비쌈
→ 가격 선호 보정
→ 주종 선호 유지
```

---

## 8.3 행동추론 저장 예시

```json
{
  "attribute_code": "ALCOHOL.DISTILLED",
  "inferred_score": 0.72,
  "source_events": [
    "PRODUCT_VIEWED",
    "FAVORITE_ADDED",
    "BOOTH_CHECKED_IN"
  ],
  "confidence": 0.81,
  "calculated_at": "2026-10-09T14:30:00+09:00",
  "expires_at": "2026-11-09T00:00:00+09:00"
}
```

# 9. 상황 프로파일

상황 프로파일은 추천 요청 시점에만 유효한 정보이다.

## 9.1 시간 상황

* 현재 시간
* 남은 체류시간
* 행사 종료까지 남은 시간
* 다음 상담까지 남은 시간
* 프로그램 시작시간
* 사용자의 희망 퇴장시간

## 9.2 공간 상황

* 현재 구역
* 선택한 출발점
* 추천 대상까지 거리
* 경로상 접근 가능 여부
* 이동제약
* 접근성 경로 필요 여부

## 9.3 운영 상황

* 부스 운영상태
* 혼잡도
* 예상 대기시간
* 제품 재고
* 시음·판매 상태
* 상담 슬롯
* 행사 공지

## 9.4 상황 프로파일 예시

```json
{
  "visit_session_id": "vs_001",
  "current_zone": "ZONE_A",
  "remaining_minutes": 55,
  "avoid_congestion": true,
  "max_walking_minutes": 10,
  "next_fixed_schedule": {
    "type": "MEETING",
    "start_at": "2026-10-09T15:00:00+09:00",
    "zone": "ZONE_C"
  }
}
```

# 10. 프로파일 속성 공통 구조

# 12. 신뢰도 모델

## 12.1 신뢰도 구성

```text
최종 신뢰도 =
출처 신뢰도
× 반복성
× 최신성
× 일관성
× 검증상태
```

## 12.2 반복성

동일 속성을 지지하는 행동이 반복될수록 신뢰도를 높인다.

```text
조회 1회
→ 낮은 신뢰

조회 3회 + 저장
→ 중간 신뢰

저장 + 방문 + 긍정 피드백
→ 높은 신뢰
```

## 12.3 일관성

서로 반대되는 행동이 함께 존재하면 신뢰도를 낮춘다.

예시:

```text
드라이 제품 반복 조회
+ 달콤한 제품 구매
→ 특정 맛의 강한 고정 선호로 판단하지 않음
```

# 13. 시간감쇠 모델

사용자 선호와 행동의 영향력은 시간에 따라 감소할 수 있다.

## 13.1 시간감쇠 기본식

```text
시간가중치 = e^(-λt)
```

* `t`: 행동 발생 후 경과시간
* `λ`: 속성별 감쇠계수

## 13.2 속성별 감쇠

| 속성        | 권장 감쇠      |
| --------- | ---------- |
| 사용자 직접 선호 | 낮음         |
| 방문목적      | 방문 종료 시 만료 |
| 현재 위치     | 수분 단위      |
| 혼잡 회피     | 행사 세션 단위   |
| 제품 조회     | 중간         |
| 구매·상담 완료  | 낮음         |
| 최근 검색어    | 높음         |
| 바이어 조직·채널 | 매우 낮음      |

---

## 13.3 세션 종료 처리

행사 방문 종료 시 다음 항목은 세션 데이터로 종료한다.

* 현재 위치
* 남은 체류시간
* 당일 제외 부스
* 당일 경로
* 당일 혼잡 회피 상태

다음 항목은 장기 프로파일 후보로 남길 수 있다.

* 실제 구매 제품
* 긍정 피드백
* 반복 조회 제품군
* 완료한 상담주제
* 명시적으로 저장한 선호

장기 TASTE.SWEET는 보조 탐색정보로만 활용
```

```

의도는 추천 대상뿐 아니라 추천 행동을 결정하는 데 활용한다.

# 18. 프로파일 충돌 처리

## 18.1 충돌 유형

* 사용자가 선택한 값과 자연어 추출값 충돌
* 장기 선호와 이번 방문 선호 충돌
* 행동추론과 직접 입력 충돌
* 필수조건과 제외조건 충돌
* 최소·최대 가격 오류
* 바이어 수량과 업체조건 해석 오류

## 18.2 처리 우선순위

```text
1. 사용자의 최근 명시적 수정값
2. 세션 목적
3. 행사 프로파일
4. 장기 프로파일
5. 행동추론
6. AI 추출
```

## 18.3 사용자 확인이 필요한 충돌

예시:

```text
가격범위: 2만~5만 원
자유입력: 10만 원 이상 프리미엄 제품
```

처리:

```text
"희망 가격대가 다르게 입력되었습니다.
이번 방문에는 어느 조건을 우선할까요?"
```

사용자 흐름을 방해하지 않도록 추천에 중대한 충돌만 확인한다.

# 30. 콜드스타트 프로파일

신규 사용자의 초기정보가 부족한 경우 다음 순서로 프로파일을 구성한다.

```text
1. 사용자 유형
2. 방문목적
3. 관심 제품군
4. 가격 또는 거래조건
5. 체류시간
6. 행동에 따라 보정
```

초기에는 3~5개 질문만으로 기본 프로파일을 생성한다.

유사 사용자 통계는 탐색 후보 생성에만 제한적으로 활용하며, 사용자의 명시적 선호로 저장하지 않는다.

콜드스타트의 세부 추천전략은 제16단계에서 확정한다.

# 34. 제7단계 검수 기준

## 데이터 구조

* 계정·행사·방문 프로파일이 분리되어 있는가
* 일반 관람객과 바이어 프로파일이 분리되어 있는가
* 명시값과 행동추론값이 구분되는가
* 미입력·중립·선호·필수·제외가 구분되는가
* 프로파일 속성별 출처와 신뢰도를 저장하는가

## 추천 활용

* 방문목적과 장기 선호의 우선순위가 정의되어 있는가
* 현재 위치·남은시간을 프로파일과 구분하는가
* 프로파일 변경 후 추천을 갱신할 수 있는가
* 추천 당시 프로파일을 재현할 수 있는가
* 낮은 신뢰도의 추론을 필수조건으로 사용하지 않는가

## 사용자 통제

* 사용자가 추론값을 확인·삭제할 수 있는가
* 개인화를 중지할 수 있는가
* 프로파일을 초기화할 수 있는가
* 직접 입력값이 AI 추론보다 우선하는가
* 동의 철회 후 행동학습을 중지하는가

## 개인정보

* 직접 식별정보가 추천 프로파일과 분리되는가
* 민감정보가 추천에 사용되지 않는가
* AI 임베딩에 직접 식별정보가 포함되지 않는가
* 사용자 삭제요청을 프로파일에 적용할 수 있는가

# 35. 제7단계 확정사항

1. 계정·행사·방문·추천세션 프로파일의 4계층 구조 적용
2. 일반 관람객과 바이어 프로파일 분리
3. 명시적 입력·행동추론·상황정보 분리
4. 사용자 직접 입력을 최우선으로 적용
5. 미입력과 비선호 상태 분리
6. 속성별 출처·신뢰도·최신성·유효기간 관리
7. 장기 선호보다 이번 방문 목적 우선
8. 행동추론은 반복성·일관성·시간감쇠 반영
9. 단일 행동으로 강한 선호 확정 금지
10. 상황 원인과 취향 원인 분리
11. 프로파일 변경 시 버전 생성 및 추천세션 갱신
12. 추천 당시 프로파일 스냅샷 저장
13. 사용자에게 추론정보 확인·수정·삭제 기능 제공
14. 직접 식별정보와 추천 프로파일 분리
15. 민감정보와 단순 인구통계의 추천 활용 제한
