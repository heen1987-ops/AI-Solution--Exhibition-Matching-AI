## 1. 재설계 기본방향

기존 30단계 순차 설계를 다음 3개 영역으로 재구성한다.

- **① 웹 초개인화 모듈** — 사전등록 사용자·바이어 대상
- **② 키오스크 이식형 검색모듈** — 현장 비등록 방문객 대상
- **③ 공통 AI·데이터 플랫폼** — 두 채널이 공동으로 사용하는 기반

각 모듈의 사용자·화면·데이터·기능·배포방식을 독립적으로 설계하고, 공통으로 사용할 요소만 백엔드에서 공유한다.

## 2. 모듈별 핵심 정의

### 2.1 웹 초개인화 모듈

- 대상: 사전등록 일반 참가자, 사전등록 바이어, 회원/인증 사용자
- 핵심 기능: 사전등록 데이터 연계, 관심 프로파일 생성, 관심분야 기반 업체·부스 추천, 개인별 행사정보 전달, 자연어 추가검색, 관심 업체 저장, 바이어·업체 매칭, 간단 상담 요청, 행사 전·중·후 정보 제공
- 서비스 성격: "사용자를 알고 있는 상태 → 먼저 맞춤정보를 제공하는 서비스"

### 2.2 키오스크 이식형 검색모듈

- 대상: 현장 비등록 방문객, 프로파일이 없는 게스트
- 핵심 기능: 다국어 시작화면, 자연어/카테고리 검색, 관련 업체·부스 목록, 상세, 지도, QR 모바일 전송, 자동 세션 초기화, 행사별 설정, 기본 로컬 캐시
- 서비스 성격: "사용자를 모르는 상태 → 현재 질문을 이해해 관련 업체를 찾아주는 서비스"

### 2.3 공통 AI·데이터 플랫폼

- 공통 기능: 업체·부스·제품 데이터 관리, 관심분야 분류체계, 자연어 의도·조건 추출, 키워드·벡터 하이브리드 검색, 업체·부스 랭킹, 추천 이유 생성, 업체정보 AI 구조화, 행사별 데이터 관리, 기본 통계·로그, 관리자 권한·승인
- 공통 사용 원칙: 웹과 키오스크는 동일한 업체·부스 정보를 사용하지만 검색과 추천 방식은 분리한다.
  - 웹 = 사용자 프로파일 + 현재 요구 + 업체정보
  - 키오스크 = 현재 질의 + 키오스크 위치 + 업체정보

## 3. 설계 진행순서 (기존 30단계 대체)

### A. 웹 초개인화 모듈 설계 (W-1~W-10)

W-1 서비스 범위·사용자 구분, W-2 사용자 여정, W-3 화면 IA, W-4 프로파일 모델, W-5 개인화 추천 로직, W-6 정보전달 정책, W-7 바이어 매칭·간단 상담, W-8 웹 API·DB, W-9 관리자 운영, W-10 검증·MVP 범위

### B. 키오스크 이식모듈 설계 (K-1~K-8)

K-1 서비스 범위, K-2 사용자 흐름, K-3 화면 IA, K-4 자연어 검색 로직, K-5 지도·위치·QR 연결, K-6 다국어·접근성, K-7 이식형 패키지 구조, K-8 검증·MVP 범위

### C. 공통 AI·데이터 플랫폼 설계 (C-1~C-8)

C-1 업체·부스 데이터 모델, C-2 업체정보 수집·AI 구조화, C-3 관심분야 온톨로지, C-4 검색·추천 공통엔진, C-5 공통 API, C-6 개인정보·권한, C-7 공통 인프라, C-8 통합시험·배포

## 4. 설계 범위에서 제외할 내용 (확장항목으로 이동)

정밀 사용자 위치추적, 복잡한 방문경로 최적화, 실시간 혼잡 추정모델, 제품별 실시간 재고관리, 장기 거래 CRM, 견적·계약·정산, 샘플 배송관리, 대규모 상담장 자동배정, 실시간 온라인 학습형 랭킹, 복잡한 공정성 최적화, 독립 마케팅 자동화 플랫폼, 키오스크 회원가입, 키오스크 장기 프로파일, 키오스크 개인정보 입력

## 5. 기존 1~28단계 설계 활용방식

| 기존 설계 | 처리 |
|---|---|
| 사용자 유형·여정 | 웹 모듈에 재사용 |
| 화면 IA | 웹·키오스크로 재분리 |
| 업체·제품 DB | 공통 플랫폼에 재사용 |
| 자연어 프로파일링 | 웹용으로 축소 |
| 자연어 검색 | 키오스크 핵심으로 이동 |
| B2C·B2B 점수 | 웹 모듈에 재사용 |
| 콜드스타트 | 키오스크 검색으로 단순화 |
| 행동학습 | 웹 등록 사용자만 제한 적용 |
| RAG·벡터검색 | 공통 검색엔진으로 재사용 |
| 상담 CRM | 간단 상담 요청만 유지 |
| 현장 관제·재고 | 기본 부스 상태만 유지 |
| 오프라인 PWA | 키오스크 로컬 캐시 수준으로 축소 |
| MLOps·DR | MVP 필요수준으로 축소 |

## 6. 이번 재설계 확정사항

1. 웹과 키오스크를 별도 서비스 모듈로 분리
2. 웹은 사전등록 사용자 초개인화 중심, 키오스크는 현장 비등록 방문객 자연어 검색 중심
3. 현장 게스트에게 지속 프로파일을 생성하지 않음
4. 키오스크는 회원가입·연락처·장기행동정보를 수집하지 않음
5. 두 모듈은 공통 업체·부스 DB와 검색엔진을 공유
6. 바이어 매칭은 웹의 독립 흐름으로 유지
7. 상담은 요청·수락 수준의 간단 기능만 MVP에 포함
8. 계약·견적·장기 CRM은 2차 확장으로 이동
9. 현장 혼잡·재고·정밀경로 기능은 기본범위에서 제외
10. 기존 설계 결과는 모듈별 참고자료로 재분류
11. 다음 단계부터 웹 모듈을 우선 설계 (W-1부터 시작)

> **주의(파일관리 담당자 메모)**: 이 문서 도착 시점까지 이미 `backend/`(FastAPI 단일 백엔드) + `frontend/`(Next.js 단일 프런트) 구조로 스캐폴딩·검증이 완료돼 있었다. 이 재설계는 `apps/user-web`, `apps/kiosk`, `apps/admin`, `apps/api`, `apps/worker` 모노레포 구조를 요구하므로, 기존 산출물과 구조적으로 다르다. 실제 리포 반영 여부는 사용자 확인 필요 — [00-roadmap.md](./00-roadmap.md)의 "재설계 반영 여부" 항목 참고.
