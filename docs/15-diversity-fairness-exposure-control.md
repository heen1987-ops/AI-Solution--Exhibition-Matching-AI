# 15단계. 다양성·공정성·추천 노출제어 구현

> 방향성 기준: [통합 설계 대화](https://chatgpt.com/share/6a6d8239-5d0c-83ee-a5b5-7505c996e874), [단계별 후속 설계 대화](https://chatgpt.com/share/6a6de70e-a640-83ee-bc1c-693ae744cbb2), 사용자 제공 제15단계 상세설계

## 구현 기준

제15단계는 제11~14단계가 계산한 관련성 점수를 다시 학습하거나 덮어쓰는 단계가 아니다. 최소 관련성 기준을 통과한 후보만 대상으로 목록 구성을 결정하며, 기업 규모·광고비·스폰서 여부는 개인화 점수에 넣지 않는다. 광고·협찬 콘텐츠는 개인화 슬레이트에서 완전히 제외하고 별도 슬롯과 지표로 다룬다.

정책은 `slate-policy-v1.0`, 정책 유형은 `SLATE_POLICY`다. 계산은 결정론적이며 같은 입력·정책·노출 스냅샷은 같은 SHA-256 지문과 결과를 만든다. Netlify AI Gateway는 자연어 조건 구조화와 추천 이유 생성용 공급자 어댑터에만 사용하며, 노출 순위·상한·공정성 판단에는 관여하지 않는다.

## 처리 흐름

```text
14단계 context_blended_score
  → 광고·후원 분리
  → 최소 관련성 하한
  → 사용자 반복노출 감점·제외
  → 조건부 기회 공정성 보정
  → MMR 재정렬
  → 업체·카테고리·지역 상한
  → 최대 1개 탐색 슬롯
  → 관련성 손실 보호
  → 슬레이트·항목 계보 저장
```

관련성 하한은 핵심 0.70, 조건부 0.55, 탐색 0.45이며 0.45 미만은 노출하지 않는다. MMR의 관련성 비중 λ는 일반 0.80, 일반 탐색 0.65, 바이어 0.85, 신규 탐색 0.70이다. `ACCURACY_FIRST`, `DIVERSE`, `NEARBY_FIRST`, `NEW_DISCOVERY` 요청 모드를 지원한다. `NEARBY_FIRST`는 14단계 상황 점수에 더해 관측된 거리 신호가 있을 때만 슬레이트 효용을 관련성 0.80·근접성 0.20으로 조정하며, 거리가 누락된 후보를 임의 원거리로 간주하지 않는다.

## 목록 제약과 탐색

- 일반 관람객: 동일 업체 상위 5개 최대 1개, 상위 10개 최대 2개, 상위 20개 최대 3개
- 바이어: 업체당 1개 카드, 적합 제품은 `related_object_ids`에 최대 3개 묶음
- 필수 주종이 아닐 때 동일 상위 카테고리 상위 5개 최대 3개, 상위 10개 최대 5개
- 필수 지역이 아닐 때 동일 지역 상위 10개 최대 4개
- 신규·탐색 슬롯은 상위 10개에서 최대 1개이며 자격 후보가 없으면 비워 둠
- 탐색 점수는 `0.55×관련성 + 0.20×데이터 품질 + 0.15×신규성 + 0.10×노출부족`이며 최종 가점은 최대 0.04

관련성 손실은 상위 5개 0.03, 상위 10개 0.05를 목표로 한다. 초과하면 MMR보다 관련성을 우선하는 제약 기반 재구성을 한 번 수행한다. 업체 상한이나 최소 관련성 때문에 두 조건을 동시에 만족할 수 없는 후보군에서는 상한을 깨거나 낮은 후보를 강제 노출하지 않고 `quality_guard_unresolved=true`를 기록해 운영 경고 대상으로 남긴다.

## 반복노출과 조건부 기회 공정성

서버가 추천 응답을 만들었다는 사실은 노출로 계산하지 않는다. 클라이언트가 카드의 실제 뷰포트 노출을 확인해 `RECOMMENDATION_IMPRESSION`을 보낸 경우에만 정규화된 노출 기록을 만든다. 이벤트에는 멱등 `client_event_id`, 저장된 추천 세션·결과·최종 순위·가시 시간이 모두 필요하며, 서버는 저장된 슬레이트 항목과 순위를 대조한다.

반복노출 범위는 부스는 방문 세션, 제품은 최근 1일, 프로그램과 업체는 행사 범위다. 긍정 행동이 없을 때 2회는 -0.03, 3회는 -0.07, 5회는 해당 범위에서 제외한다. 열기·저장·부스 체크인·상담 요청은 반복 감점을 해제한다.

공정성은 모든 업체를 동일하게 노출하는 방식이 아니라 적격 후보 비중 대비 실제 노출이 부족한 업체에 제한된 기회를 주는 방식이다. 보정은 ±0.05, 집중도 감점은 최대 0.05다. 관련성·필수조건·운영상태·데이터 품질 기준을 통과하지 못한 업체는 공정성 보정 대상이 아니다.

## 저장 계약

| 테이블 | 책임 |
|---|---|
| `matching.match_policy_version` | 게시된 `slate-policy-v1.0` 설정과 해시 |
| `matching.slate_result` | 세션별 정책 FK, 입력·결과 지문, ILD·커버리지·공정성·관련성 손실 |
| `matching.slate_item` | 보정 전후 순위·점수, MMR, 보정·감점, 슬롯, 묶음 제품, 항목 지문 |
| `interaction.recommendation_impression` | 실제 가시 노출과 사용자·게스트·방문 세션, 슬레이트 항목의 append-only 연결 |

세 테이블은 tenant·event 경계를 복합 FK로 검증하고 결과와 노출 기록의 UPDATE·DELETE를 트리거로 막는다. `slate_result`와 `slate_item`은 과거 추천을 재현하는 정본 결과이며, 노출 집계는 별도 overlay다.

운영 지표는 ILD, 카테고리·업체 커버리지, Exposure Fairness Score, Gini, HHI, 탐색 슬롯 수, 반복 제외 수, 광고 분리 수, 상위 5·10 관련성 손실을 정책 버전별로 저장한다.

## backju.kr `/adm/` 이식성

`https://www.backju.kr/adm/`은 공개된 관리자 API 계약이 아니라 현재 오류 안내 페이지이므로 구현은 PHP 경로·세션·내부 DB 스키마를 참조하지 않는다. 기존 사이트는 서명된 사이트 컨텍스트와 표준 REST API 또는 웹훅·CSV 어댑터만 사용한다.

추천 카드는 `slot_type`과 `related_object_ids`만 추가로 렌더링하면 된다. 실제 노출은 `IntersectionObserver` 등으로 확인한 뒤 `POST /api/v1/interactions/batch`에 전송한다. 이 방식은 동일 도메인 리버스 프록시, 외부 위젯, 별도 운영 콘솔 중 어느 배포 방식에서도 같은 정책·DB 계보를 유지한다.

## 검증 결과와 다음 단계

단위 테스트는 업체 상한, 대표제품 묶음, 관련성 하한, 광고 분리, 탐색 슬롯, 반복 감점 해제, 바이어 1업체 1카드, 공정성 보정 한계, 결과 재현성, 관련성 보호를 검증한다. API 계약 테스트는 실제 노출 이벤트가 저장된 슬레이트 항목과 순위를 통과한 경우에만 정규화 노출로 저장되는지 확인한다. Alembic `0011_slate_policy`는 단일 head이며 upgrade·downgrade SQL을 검증한다.

개발 환경의 순수 슬레이트 함수 40회 측정에서 후보 100개 P95 32.62ms, 후보 300개 P95 105.76ms로 각각 목표 100ms·250ms 이내였다. 이 수치는 DB 노출 이력 조회를 제외한 정책 계산 기준이며, 운영 P95는 사용자·게스트·방문 세션 인덱스가 적용된 PostgreSQL에서 별도로 계측한다.

다음 구현 단위는 제16단계 콜드스타트 대응이다. 신규 사용자·바이어·업체·제품의 부족한 신호를 구분하고, 최소 질문·품질 후보·온톨로지 유사도·탐색 정책을 결합하되 제15단계 최소 관련성과 노출 상한을 그대로 통과시킨다.
