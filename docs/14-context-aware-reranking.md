# 14단계 — 상황인지 실시간 재정렬 구현

## 방향성 기준

2026-08-01에 [전체 설계 대화](https://chatgpt.com/share/6a6d8239-5d0c-83ee-a5b5-7505c996e874)와 [현재 단계 설계 대화](https://chatgpt.com/share/6a6de70e-a640-83ee-bc1c-693ae744cbb2)를 다시 확인했다. 현재 대화는 13단계 양면 적합도 다음 작업을 위치, 잔여시간, 혼잡, 재고, 상담일정, 경로, 운영상태를 반영하는 14단계로 지정한다. 이 구현은 [5단계 매칭엔진 §5.9](./05-ai-matching-engine-architecture.md)의 원칙대로 기본 적합도와 “지금 방문할 가치”를 분리한다.

## 점수 계약

정책 버전은 `context-rerank-v1.0`, 정책 유형은 `CONTEXT_RERANK`다. 외부 AI 모델을 호출하지 않는 결정론적 계산이며 `matching.match_policy_version`과 `matching.match_weight`에 게시한다.

```text
final_score = base_score × 0.85 + context_score × 0.15
```

관측된 컨텍스트가 하나도 없으면 `context_score = NULL`로 남기고 `final_score = base_score`를 유지한다. 일부 신호만 있으면 관측된 신호의 가중치만 합계 1로 재정규화한다. 누락값을 0.5 같은 가상 중립값으로 채우지 않는다.

| 구성요소 | 기본 가중치 | 입력 |
|---|---:|---|
| proximity | 20% | 현재 구역과 대상 좌표의 도보거리 |
| time_feasibility | 20% | 잔여시간 대비 이동·대기·기본 방문시간 |
| wait_congestion | 15% | 대기분, 혼잡도, 혼잡회피 선호 |
| operational_availability | 15% | 부스·제품·프로그램·참가 운영상태 |
| meeting_availability | 10% | 바이어 상담 슬롯 또는 확정 상담 |
| schedule_feasibility | 10% | 다음 확정 일정까지 방문·이동 가능성 |
| inventory_urgency | 5% | 판매 가능 제품의 재고 임박 상태 |
| recent_behavior | 5% | 최근 30분 조회·이미 방문한 부스 |

## 재현성과 저장

각 `match_result`는 다음 계보를 과거 결과에 덮어쓰지 않고 보존한다.

- 컨텍스트 정책 FK와 정책 버전
- 구성요소 원값, 누락 목록, 유효 가중치, 항목별 기여도
- 현재 구역, 잔여시간, 최근 행동, 확정 일정, 후보 운영상태를 포함한 입력 SHA-256 지문
- 기본점수·컨텍스트점수·최종점수를 포함한 계산 SHA-256 지문
- 거리, 도보·대기시간, 상태 관측시각, 가용성, 운영 스냅샷 버전

같은 입력과 정책은 같은 두 지문과 점수를 만든다. 위치·시간·혼잡·재고·상담 상태가 바뀌면 입력 지문이 달라지므로 [인터페이스 명세 §9.3](./frontend-backend-ai-interface-spec.md)의 재생성 조건을 판정할 수 있다.

## backju.kr `/adm/` 이식성

`/adm/`은 현재 공개된 안정 API가 아니라 오류 안내 화면이므로 PHP 세션, 관리자 URL, 내부 테이블을 재정렬 계약으로 사용하지 않는다. 기존 사이트는 [서명형 사이트 컨텍스트 어댑터](./12-recommendation-api-implementation.md)를 통해 위치·잔여시간 등 제공 가능한 값만 전달한다.

상담·좌표·혼잡·재고 모듈은 선택 기능이다. 상담 테이블은 `to_regclass`로 감지하며, 미설치 상태를 “상담 불가 0점”으로 오판하지 않고 해당 구성요소를 제외한다. 좌표나 운영 관측값이 없을 때도 같은 방식으로 축소 동작한다. 따라서 API, 동일 도메인 프록시, 별도 운영 콘솔, CSV 교환 중 어느 연결 방식에서도 동일 정책을 재사용할 수 있다.

## AI Gateway 경계

Netlify AI Gateway는 이 점수 계산에 관여하지 않는다. 이후 자연어 요구조건 추출이나 사용자용 설명을 추가할 때만 공급자 비종속 어댑터 뒤에서 호출한다. AI 출력은 후보 제안이며 온톨로지·스키마·근거 검증을 통과하기 전에는 정책 점수나 운영상태를 변경할 수 없다.

## 검증과 한계

- 가까운 저대기 후보와 시간상 불가능한 후보의 순위 역전 검증
- 누락 신호 재가중과 선택 상담 모듈 미설치 축소 동작 검증
- 확정 상담 경로 불가능성 검증
- 동일 입력 재현 및 컨텍스트 변경 시 지문 회전 검증
- 런타임 정책과 Alembic 시드 가중치 일치 검증
- 결과 저장 정책 FK·구성요소·기여도·지문 계약 검증

운영 스냅샷의 전역 단조 버전 테이블은 아직 없어서 세션에는 분 단위 버전을 기록한다. 다만 결과별 입력 지문에는 실제 후보 상태·관측시각·일정이 포함되어 재현성을 보완한다. 운영 이벤트 스트림과 전역 스냅샷 카운터는 23단계 데이터 파이프라인에서 추가한다.

다음 구현 단위는 15단계 다양성·공정성 정책을 게시 가능한 버전 계약으로 승격하고, 14단계 최종점수 이후의 노출 상한·중복 제한·탐색 슬롯을 결과 계보에 저장하는 것이다.
