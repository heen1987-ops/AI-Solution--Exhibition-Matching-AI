# 백주 AI 셀파 사용자 화면 IA·와이어프레임

> 문서 상태: MVP 구현 기준안 v1.0  
> 기준일: 2026-07-31  
> 상위 문서: [2026 대한민국 백주대간 초개인화 AI 매칭서비스 통합 설계안](./2026-backju-ai-matching-service-design.md)
> API·AI 계약: [프론트엔드·백엔드·AI 인터페이스 명세](./frontend-backend-ai-interface-spec.md)

## 1. 설계 목표

- 사전등록자와 현장 방문자가 앱 설치 없이 모바일 웹·QR로 진입한다.
- 최초 5~7개 질문, 60~90초 이내에 최소 프로파일을 완성한다.
- 추천을 정보 열람에서 끝내지 않고 저장·경로·QR 방문·상담으로 전환한다.
- 일반 관람객과 바이어의 입력·추천·상담 흐름을 분리한다.
- 사용자의 명시적 행동과 현장 상태에 따라 다음 추천을 갱신한다.
- 개인화에 동의하지 않아도 일반 검색·지도·행사정보는 사용할 수 있다.

### 1.1 UX 원칙

1. 모바일 세로 화면과 한 화면 한 행동을 우선한다.
2. 필수 질문과 점진적 보강 질문을 분리한다.
3. 추천 이유는 사용자가 입력한 목적·조건과 검증된 운영정보로 설명한다.
4. 현재 할 행동을 긴 목록보다 먼저 보여준다.
5. 위치는 정밀 추적 대신 입구·구역·부스 QR로 갱신한다.
6. 회원가입을 진입 조건으로 강제하지 않는다. 저장·상담 등 본인 연결이 필요한 시점에만 OTP 인증을 요구한다.
7. 오류·정보 부족·네트워크 단절도 정상 상태로 설계한다.

## 2. 사용자와 권한

| 사용자 | 핵심 목표 | 인증 수준 | 개인정보 노출 |
|---|---|---|---|
| 익명 현장 관람객 | 빠른 추천·탐색 | 익명 세션 | 본인 입력만 |
| 인증 관람객 | 저장·일정·방문이력 | 휴대전화 OTP 또는 서명 링크 | 본인 데이터 |
| 바이어 | 업체 비교·상담 요청 | OTP, 필요 시 소속 확인 | 본인·동의한 상담정보 |
| 참가업체 담당자 | 상담 수락·리드 기록 | 파트너 계정, MFA 권장 | 동의 범위의 마스킹 정보 |
| 운영자 | 승인·상태·성과·민원 | 역할 기반 계정, MFA 필수 | 역할별 최소 범위 |

참가업체 포털에서는 상담 수락 전 바이어 연락처를 표시하지 않는다. 상담 수락과 사용자의 연락처 공유 동의가 모두 충족된 경우에만 필요한 연락정보를 공개하고 열람 이력을 남긴다.

## 3. 전체 IA

```text
[진입]
 ├─ 사전등록 완료 서명 링크
 ├─ 홈페이지 AI 추천 메뉴
 ├─ 입구·구역·부스 QR
 └─ 현장 키오스크 QR
        │
        ▼
[시작·자격·동의]
 ├─ 서비스 소개
 ├─ 사용자 유형
 ├─ 만 19세 이상 확인
 └─ 개인화·행동정보·마케팅·연락처 공유 동의
        │
        ▼
[최소 프로파일]
 ├─ 공통: 방문 목적·시간·이동 선호
 ├─ 관람객: 주종·맛·도수·가격
 └─ 바이어: 채널·제품·가격·MOQ·공급지역
        │
        ▼
[행동 중심 홈]
 ├─ 지금 방문할 부스
 ├─ 오늘의 추천 경로
 ├─ 다음 상담·프로그램
 └─ 추천 조건 수정
        │
        ├──────────────┐
        ▼              ▼
[탐색·지도]        [상담·일정]
 ├─ 부스·제품       ├─ 요청
 ├─ 추천 전체       ├─ 상대 응답
 ├─ 저장·비교       ├─ 확정·변경
 └─ 경로            └─ 결과·후속조치
        │
        ▼
[현장 행동]
 ├─ QR 체크인
 ├─ 시음·구매·상담
 ├─ 짧은 피드백
 └─ 다음 추천 갱신
        │
        ▼
[MY·권리관리]
 ├─ 일정·저장·방문·상담 이력
 ├─ 추천 조건·프로파일 초기화
 └─ 동의·다운로드·삭제·탈퇴
```

## 4. 글로벌 내비게이션

### 4.1 모바일 하단 탭

| 탭 | 경로 | 역할 |
|---|---|---|
| 홈 | `/home` | 현재 상황에 따른 다음 행동 |
| 탐색 | `/explore` | 부스·제품·프로그램 검색 |
| 지도 | `/map` | 현재 구역, 부스 위치, 추천 경로 |
| 일정 | `/schedule` | 방문계획·상담·프로그램 |
| MY | `/my` | 저장·이력·프로파일·동의 |

하단 탭은 5개를 넘기지 않는다. 상담은 별도 탭을 만들지 않고 홈·일정·업체 상세에서 진입한다.

### 4.2 상단 공통 영역

- 행사 로고 또는 축약 행사명
- 선택한 방문일
- 현재 구역과 `위치 갱신` 액션
- 동기화 또는 네트워크 상태
- 알림 진입점은 2차 확장
- 추천 조건 수정은 홈·목록의 명시적 액션으로 제공

## 6. 상태 모델

### 6.1 온보딩

```text
anonymous
  → role_selected
  → age_eligibility_confirmed
  → privacy_choice_recorded
  → minimum_profile_completed
  → recommendation_ready
```

- 만 19세 이상 확인이 없으면 주류 개인화 서비스에 진입할 수 없다.
- 개인화에 동의하지 않으면 `general_browse`로 분기한다.
- 중간 이탈 시 익명 세션에 답변을 저장하고 같은 브라우저에서 재개한다.
- 만료된 서명 링크 또는 세션은 새 세션 생성과 본인 인증 선택지를 제공한다.

### 6.2 상담

```text
draft
  → requested
  → accepted → completed
  → counter_proposed → accepted
  → rejected
  → cancelled
  → no_show
```

모든 전이에는 행위자, 시각, 이전·이후 상태, 사유를 남긴다. `requested` 이후 중복 제출은 동일 멱등 키로 같은 결과를 반환한다.

### 6.3 부스 운영

```text
open
  ↔ busy
  ↔ tasting_closed
  ↔ sold_out
  → closed
```

`sold_out`은 특정 제품 단위 상태가 우선이며 모든 제품이 품절일 때만 부스 상태로 승격한다. `tasting_closed` 상태에서도 전시·상담·구매가 가능할 수 있으므로 가능한 행동을 별도 필드로 표현한다.

### 6.4 오프라인 동기화

```text
local_only → queued → sending → synced
                       └→ retryable_error → queued
                       └→ final_error
```

## 7. 핵심 화면 와이어프레임

### U-01 시작

```text
┌────────────────────────────┐
│ 2026 대한민국 백주대간       │
│ 백주 AI 셀파                 │
├────────────────────────────┤
│ 나에게 맞는 술·양조장과      │
```

직접 입력은 LLM이 구조화하되 사용자가 변환 결과를 다음 화면에서 확인·수정할 수 있어야 한다.

### U-05 관람객 취향

4개의 짧은 카드로 제공한다.

1. 주종: 탁주, 약주·청주, 증류주, 과실주, 기타주류, 잘 모르겠음
2. 맛·향: 달콤, 드라이, 산뜻, 묵직, 향이 강함, 부드러움
3. 도수: 낮음, 중간, 높음, 상관없음
4. 가격: 2만 원 이하, 2~5만 원, 5~10만 원, 품질 우선, 구매 계획 없음

모든 질문은 건너뛰기와 `잘 모르겠음`을 제공하며, 선택 즉시 저장한다.

사용자 화면에는 `92점`, `98.7% 일치` 같은 정밀해 보이는 내부 점수를 기본 노출하지 않는다. `조건이 잘 맞아요`, `희망 가격대 일치`처럼 검증 가능한 근거를 보여준다.

```text
┌────────────────────────────┐
```

추천 인상 이벤트는 카드가 실제 뷰포트에 노출된 경우에만 한 세션·한 추천버전당 한 번 기록한다.

### U-10 부스 상세

필수 영역:

- 업체명, 부스번호, 거리 또는 구역
- 검수된 대표 이미지와 소개
- 사용자의 추천 근거
- 대표 제품, 주종, 가격대
- 현재 가능한 행동: 시음, 구매, 상담
- 운영·혼잡·품절 상태와 갱신시각
- 지도, 일정 추가, 상담 요청, 저장

운영정보가 없거나 오래된 경우 `현재 상태 미확인`으로 표시한다. 추정값을 사실처럼 보여주지 않는다.

### U-11 제품 상세

필수 영역:

- 제품·업체·이미지
- 주종, 도수, 원료, 맛·향, 용량, 가격
- 시음·구매·택배 가능 여부
- 정보 갱신시각과 업체 확인 여부
- 부스 방문, 유사 제품, 저장

가격·재고가 제공되지 않은 경우 빈 값을 `문의` 또는 `정보 없음`으로 명시한다.

### U-13 지도·추천 경로

```text
┌────────────────────────────┐
│ 추천 방문경로               │
├────────────────────────────┤
│ [행사장 지도]                │
│ 현재 구역 ●                  │
│ ① A양조장                    │
│ ② B주조                      │
│ ③ 시음 프로그램              │
├────────────────────────────┤
│ 약 55분 · 이동 12분          │
│ [경로 시작] [순서 변경]       │
│ [혼잡 부스 제외]             │
└────────────────────────────┘
```

현재 위치는 `최근 QR: B구역 · 14:22`처럼 출처와 시각을 함께 표시한다. QR 스캔이 어려운 사용자는 지도에서 현재 구역을 직접 선택할 수 있다.

### U-14 상담 요청

```text
┌────────────────────────────┐
│ A양조장 상담 요청            │
├────────────────────────────┤
│ 상담 주제                   │
│ [입점·유통] [OEM·PB] [수출]  │
│ [제품·가격] [기술·설비]       │
│                            │
│ 희망시간                    │
│ [14:30] [15:00] [16:00]     │
│                            │
│ 전달할 내용 [____________]   │
│                            │
│ □ 수락 시 연락처를 공유합니다 │
│ 공유 항목 자세히 보기         │
│                            │
│ [상담 요청 보내기]           │

```

전송 버튼을 누르면 외부 상대에게 요청이 전달되므로 제출 직전에 업체, 시간, 공유정보를 요약한다. 전송 중 버튼을 잠그고 멱등 키로 중복 요청을 막는다.

### U-15 상담 상태

`업체 확인 중`, `시간 변경 제안`, `확정`, `거절`, `취소`, `완료`를 하나의 상태 화면에서 처리한다. 확정 화면에는 업체·시간·부스·주제와 지도·변경·취소 액션을 제공한다.

### U-16 QR 체크인

```text
┌────────────────────────────┐
│ A양조장 방문 확인            │
├────────────────────────────┤
│ 무엇을 하셨나요?             │
│ [시음] [구매] [상담]         │
│ [정보 확인] [대기 후 이탈]    │
│                            │
│ [저장하고 다음 추천]          │
└────────────────────────────┘
```

- QR 토큰은 부스·행사·만료시간을 서명하며 사용자 ID를 포함하지 않는다.
- 같은 사용자의 짧은 시간 내 중복 스캔은 하나의 방문으로 묶는다.
- 카메라 권한을 거부해도 QR 링크 직접 접속 또는 코드 입력으로 체크인할 수 있다.

### U-17 피드백

- 한 번의 적합도 선택과 선택형 이유로 5초 안에 끝낸다.
- 서술형 입력은 선택사항이다.
- 피드백 저장 직후 다음 추천을 보여준다.
- `부적합`은 사용자가 원하면 해당 업체·제품을 이후 추천에서 제외한다.

### U-18 일정

방문·상담·프로그램을 하나의 타임라인에 표시한다. 상담 일정은 시간 충돌을 허용하지 않고, 일반 부스 방문은 예상시간이 겹치면 경고만 제공한다.

### U-19 관심목록

부스·제품·상담을 구분하고 `미방문`, `방문 완료`, `상담 예정`, `운영 종료` 상태를 보여준다. 익명 사용자의 저장목록은 브라우저 로컬에 보관하고 인증 시 명시적으로 계정에 합친다.

### U-20 추천 조건 수정

목적, 주종, 가격, 남은 시간, 이동 선호를 한 화면에서 수정한다. 변경 후 새 추천버전을 생성하고 이전 추천을 감사·분석 목적으로 보존한다.

### U-22 MY·동의관리

- 추천 프로파일과 조건
- 관심목록, 방문·상담 이력
- 개인화·행동정보·마케팅·연락처 공유 동의
- 개인정보 열람·다운로드 요청
- 프로파일 초기화
- 계정 연결 해제·탈퇴·삭제 요청

동의 철회 결과를 즉시 설명한다. 예를 들어 행동정보 동의를 철회하면 신규 행동을 개인화에 사용하지 않으며, 이미 수집된 데이터의 처리·삭제 범위와 완료예정일을 별도로 안내한다.

- 소속·담당업무·유통채널

- 공유에 동의한 항목만 표시
- 휴대전화·이메일은 기본 마스킹
- 연락처 열람 시 목적 확인과 감사로그 기록

## 11. 예외·오류·오프라인

### 11.1 추천 없음

정확히 일치하는 결과가 없음을 설명하고, 어떤 조건을 완화하면 몇 개 결과가 생기는지 보여준다.

- `조건 완화해서 보기`
- `추천 조건 수정`
- `직접 탐색`

절대조건은 사용자의 명시적 동의 없이 자동 완화하지 않는다.

### 11.2 운영 종료·품절

선택한 대상의 상태와 갱신시각을 표시하고, 같은 목적을 충족하는 대체 부스·제품을 제시한다.

### 11.3 일정 충돌

충돌하는 기존 일정과 가능한 대체시간을 보여준다. 상담 확정 일정은 자동으로 덮어쓰지 않는다.

### 11.4 네트워크 단절

- 최근 추천, 저장목록, 일정, 부스 기본정보를 오프라인 캐시
- 연락처·동의 원문 등 민감정보는 브라우저 캐시에 저장하지 않음
- QR 체크인·피드백·상담요청은 멱등 키와 함께 로컬 큐에 임시저장
- 재연결 시 자동 재전송하고 성공·실패 상태를 사용자에게 표시
- 상담요청처럼 외부 상대에게 전달되는 작업은 장시간 지연 시 재확인

## 13. 반응형·접근성

### 13.1 반응형

- 모바일: 360~430px, 카드 1열, 하단 탭·핵심 CTA 고정
- 태블릿·키오스크: 추천·지도 2분할, 카드 2~3열
- 데스크톱: 좌측 필터, 중앙 목록, 우측 상세; 바이어 비교·일정 중심
- 고정 CTA는 iOS·Android 안전영역을 침범하지 않는다.

### 13.2 접근성 완료 조건

- 기본 본문 16px 이상, 200% 확대에서도 기능 손실 없음
- 터치 영역 최소 44×44px
- 일반 텍스트 대비 4.5:1 이상
- 키보드만으로 모든 기능 사용 가능
- 입력·오류·상태 변경에 스크린리더 레이블과 라이브 알림 제공
- 지도 정보는 목록·텍스트 경로로도 제공
- 색상만으로 선택·품절·혼잡을 구분하지 않음
- 애니메이션 감소 설정 지원
- 카메라 없이 QR 체크인 가능한 대체수단 제공

MVP에서도 비교 버튼이 보이면 안 된다. 확장 기능은 비활성 UI로 예고하지 않고 실제 제공 시점에 노출한다.

## 15. 구현 완료 기준

### 15.1 온보딩

- 신규 사용자가 7개 이하의 필수 질문으로 추천에 도달한다.
- 이전·건너뛰기·중간 이탈·재개가 동작한다.
- 관람객과 바이어 질문이 올바르게 분기된다.
- 개인화 거부 시 일반 탐색으로 진입한다.

### 15.2 추천

- 카드에 실제 데이터에 근거한 추천 이유와 상태 갱신시각이 표시된다.
- 정보 없음·추천 없음·운영 종료·오프라인 상태가 처리된다.
- 저장·제외·경로·상세 행동이 새 추천버전과 연결된다.

### 15.3 방문·경로

- 입구·구역·부스 QR 또는 직접 선택으로 현재 구역을 갱신한다.
- 중복 QR 스캔이 중복 방문으로 과대 집계되지 않는다.
- 최근 추천·일정·부스 기본정보가 네트워크 단절 중에도 열린다.

### 15.4 상담

- 바이어만 상담을 요청할 수 있다.
- 요청 전 업체·시간·공유정보를 확인한다.
- 중복 제출이 발생하지 않는다.
- 수락·변경제안·거절·취소·완료 전이가 감사로그와 함께 저장된다.
- 공유 동의와 수락 전에는 연락처가 노출되지 않는다.

### 15.5 권리·보안

- 동의 목적별 상태와 버전을 조회·변경할 수 있다.
- 프로파일 초기화와 삭제 요청 결과를 안내한다.
- 분석 이벤트와 브라우저 캐시에 직접 식별정보가 남지 않는다.
- 파트너·운영자 권한을 우회해 다른 업체·사용자 데이터에 접근할 수 없다.
