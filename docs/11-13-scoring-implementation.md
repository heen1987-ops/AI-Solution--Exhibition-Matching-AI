# 11~13단계 결정론적 점수 코어 구현 기록

## 기준

- 공유 설계 대화: <https://chatgpt.com/share/6a6de70e-a640-83ee-bc1c-693ae744cbb2>
- 첨부 원문: 제11단계 일반 관람객 점수, 제12단계 바이어 점수, 제13단계 양면 적합도
- 상위 원칙: `docs/05-ai-matching-engine-architecture.md`

이 구현은 생성형 AI가 추천순위나 필수조건을 직접 결정하지 않도록 한다. AI가 이후
자연어 조건이나 설명문을 제안하더라도, 승인된 구조화 값과 버전이 고정된 정책만 이 계산기에
전달한다. 외부 모델은 Netlify AI Gateway 뒤의 별도 어댑터로 연결하고 계산 코어에는 공급자
SDK나 모델 식별자를 두지 않는다.

## 구현 범위

`src/meet_ai/scoring`은 다음 계약을 제공한다.

1. 10단계 Hard Filter가 통과한 후보만 점수 계산을 허용한다.
2. 누락된 구성요소는 0점으로 처리하지 않고 가중치 분모에서 제외한다.
3. 명시적인 0점은 불일치 신호로 계산에 포함한다.
4. 정책에 없는 구성요소는 자동 수용하지 않고 오류로 처리한다.
5. 정보 부족·근거 부족 등의 점수 상한은 코드와 함께 결과에 보존한다.
6. 정책 버전, 입력값, 적용 상한과 필터 평가 ID로 SHA-256 계산 지문을 만든다.
7. 바이어→업체와 업체→바이어 점수는 분리하고, 양면 점수는 조화평균으로 결합한다.
8. 최소방향 점수 상한, 방향 불균형, 신뢰도, 신규 거래 수용성을 서로 다른 값으로 보존한다.

## 설계 원문 보정

### B2C 예시 합계

11단계 예시의 기재 결과는 `95.75`지만, 같은 예시에 제시된 가중치와 구성요소를 그대로
더하면 `95.95`다.

```text
0.20 + 0.18 + 0.18×0.90 + 0.12 + 0.08
+ 0.09 + 0.06 + 0.04×0.50 + 0.05×0.95
= 0.9595
```

재현 가능한 정책 계약을 우선하여 실행 결과는 `95.95`로 확정한다. 설계 문서의 예시 숫자는
후속 개정 시 수정해야 한다.

### 양면 점수 반올림

13단계 예시는 `92`와 `88`의 조화평균을 `89.96`으로 표시한 뒤 보정하여 `86.88`을
산출한다. 반올림하지 않은 조화평균을 끝까지 사용하면 마지막 값이 `86.87`이 될 수 있다.
서로 다른 런타임에서도 같은 결과를 내기 위해 다음 규칙을 명시했다.

```text
조화평균을 소수 둘째 자리 ROUND_HALF_UP으로 확정
→ 신뢰도·수용성 보정
→ 불균형 패널티와 정책 보정 적용
```

이 반올림 규칙도 계산 지문의 정책 정보에 포함한다.

## 클로드 구현과의 연결 경계

클로드가 작성한 `backend/app/services/matching`은 요청 검증, 프로파일 해석, 상황 해석과
파이프라인 오케스트레이션을 담당한다. `base_scoring` 및 `reciprocal_matching` 단계는 이제
이 순수 코어를 호출하며, 필터 평가 ID 없이 계산을 시작하지 않는다.

- 서비스 계층: DB 조회, 온톨로지 해석, 후보 특징 구성
- 순수 계산 코어: 정규화, 점수, 상한, 등급, 양면 결합, 계산 지문
- 영속화 계층: 필터 평가, 정책 버전, 방향별 결과, 양면 결과, 추천 근거 저장

서비스 계층에서 같은 산식을 다시 구현하지 않는다.

백엔드 후보 객체에는 방향별 구성요소, 유효 가중치, 기여도, 결측 구성요소, 신뢰도, 정책
버전과 계산 지문을 보존한다. 양면 계산에는 조화평균, 최소방향 게이트, 불균형 패널티,
신뢰도·수용성 보정, 외부 상한과 최종 상태를 각각 분리해 보존한다.

기존 PHP 관리자 사이트와의 이식 경계는 `docs/backju-adm-portability.md`에 정의한다. 점수
코어는 PHP 세션이나 `/adm/` 내부 DB 구조에 의존하지 않는다.

## 정책·모델·결과 영속화 보정

정책 버전은 개별 행사 DB에 복제하지 않고 `matching.match_policy_version`에 불변 전역
아티팩트로 게시한다. 행사별 선택은 `matching.event_policy_binding` 오버레이가 담당한다.
이는 초기 ERD의 행사별 정책 컬럼을 정규화한 의도적 예외이며, 동일 점수 코어를 여러 행사와
기존 `/adm/` 사이트에 이식할 때 정책 정의의 중복과 드리프트를 막는다.

결과 저장은 더 이상 존재하지 않는 정책·모델 ID를 임시 UUID로 만들거나 실패를 삼키지 않는다.
게시 정책, 배포 모델, 택소노미, 프로파일 버전, 필터 평가, 추천대상 레지스트리가 모두 실제 FK로
확인될 때만 한 트랜잭션으로 커밋한다. `matching.match_result`에는 방향별 구성요소·유효 가중치·
기여도·결측·신뢰도·계산 지문과 양면 점수 세부값을 함께 보존한다.

`ai.model_version`과 append-only `ai.ai_run`은 공급자 중립 레지스트리다. 현재 랭킹은 외부 추론이
없는 결정론 코어로 등록하고, 향후 비정형 특징 추출·설명 모델만 Netlify AI Gateway 어댑터 뒤에
연결한다. 비밀키, 전체 프롬프트, 원문 모델 응답은 DB에 저장하지 않는다.
