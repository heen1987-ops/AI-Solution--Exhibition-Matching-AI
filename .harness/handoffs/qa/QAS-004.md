# QAS-004 Handoff

## 완료 내용

프런트 3개 앱(user-web, kiosk, admin)에 대한 Playwright smoke E2E 하네스를 추가했다.

## 변경 파일

- `package.json`
- `package-lock.json`
- `playwright.config.ts`
- `tests/e2e/README.md`
- `tests/e2e/wave1-smoke.spec.ts`
- `.harness/backlog.yaml`
- `.harness/state.json`
- `.harness/quality-gates.yaml`
- `.harness/run-log.md`

## 공개 인터페이스

- 루트 npm script: `npm run e2e`
- E2E 전용 포트:
  - user-web: `http://127.0.0.1:3300`
  - kiosk: `http://127.0.0.1:3310`
  - admin: `http://127.0.0.1:3320`

## 테스트 흐름

- user-web: `/home` -> `/search` -> 검색 제출 -> `/companies/c-001`.
- kiosk: `/` -> `/language` -> `/search` -> `/results` -> `/exhibitors/exh-001` -> `/map`/`/qr` -> `/`.
- admin: `/` -> `/console`, 업체·제품 검수/AI 추출 검수 예정 카드 표시.

## 검증

- 최초 `npm run e2e`: Playwright Chromium 미설치로 실패.
- `npx playwright install chromium`: 성공.
- 두 번째 `npm run e2e`: user-web이 기존 3000번 포트의 다른 앱을 재사용해 실패,
  kiosk sessionStorage 잔존 검사를 추가로 걸어 실패.
- 포트를 3300/3310/3320으로 조정하고, QAS-004 smoke 범위를 실제 라우트 흐름 검증으로
  정리한 뒤 최종 `npm run e2e`: 3 passed.

## 알려진 제한

- admin 상세/검수탭은 아직 제품 골격에 없어서 `/console`의 검수 예정 카드까지만 검증했다.
  Wave 2 `ADM-GROUP-001`에서 실제 상세/검수 화면이 생기면 목록 -> 상세 -> 검수 탭 흐름으로
  확장해야 한다.
- kiosk 루트 재진입만으로 `sessionStorage`가 자동 삭제되지는 않는 것을 E2E 작성 중 확인했다.
  이 항목은 QAS-004 smoke를 넘는 KSK-GROUP-001 세션 초기화 잔여위험으로 남긴다.
- `npm install --save-dev @playwright/test` 후 `npm audit`이 12건(1 low, 3 moderate,
  7 high, 1 critical)을 보고했다. QAS-004 범위가 아니므로 자동 수정하지 않았다.

## 되돌리는 방법

  `package-lock.json`의 `@playwright/test` 및 `e2e` script 추가분을 되돌리면 된다.
