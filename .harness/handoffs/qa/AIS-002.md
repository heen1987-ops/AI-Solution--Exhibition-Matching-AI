# AIS-002 - 온톨로지 유사어 해석 테스트셋

## 완료 내용

`backend/tests/test_ontology_api.py`에 온톨로지 유사어 해석(`POST /api/v1/ontology/resolve`,
내부적으로 `src/meet_ai/ontology/catalog.py`의 `Catalog.resolve_synonym(text, *, locale, context)`
호출) 테스트 7건을 추가했다(기존 4건 + 신규 7건 = 총 11건).

작업 전 `src/meet_ai/ontology/catalog.v1.json`을 직접 조사해 실제 데이터만 근거로 테스트를
작성했다:

- `synonyms` 배열은 총 11건이며, **전부 `locale: "ko-KR"`**이다. `locale: "en-US"`(또는
  그 외 영문 로케일) 유사어는 **단 하나도 존재하지 않는다**.
- 컨텍스트는 `PRODUCT`(2건: 막걸리→ALCOHOL.TAKJU, 전통 소주→ALCOHOL.SOJU_DISTILLED),
  `CONSUMER`(5건: 달지 않은→TASTE.DRY, 목 넘김이 좋은→TASTE.SMOOTH, 독하지 않은→TASTE.MILD,
  향긋한→AROMA.FLORAL/AROMA.FRUIT[중의적], 선물하기 좋은→USE.GIFT),
  `BUYER`(4건: 바틀샵 납품→CHANNEL.BOTTLE_SHOP, 자체 브랜드→TRADE.PRIVATE_LABEL,
  정기 납품→TRADE.REGULAR_SUPPLY)로 구성된다. `context: "ANY"`(모든 컨텍스트에 매치)인
  유사어는 아직 없다.

이 발견(영문 유사어 부재)을 지어낸 매칭 쌍으로 감추지 않고, 테스트에서 그대로
"현재 동작을 고정하는 회귀 테스트"로 반영했다 - 아래 RISKS 참고.

## 알려진 제한

- **영문(en) 유사어 해석의 "성공" 케이스는 작성하지 않았다** - 카탈로그에 영문 유사어
  데이터가 없어 지어낼 수 없었기 때문이다. 대신 `test_resolve_en_locale_has_no_synonym_coverage_yet`
  테스트로 "로케일 불일치 시 안전하게 0건 반환"이라는 현재 동작을 문서화하고 고정했다.
  이는 다국어 acceptance 기준(`backlog.yaml` AIS-002: "다국어(ko/en) 유사어 해석 케이스
  포함")을 문자 그대로의 "en 매칭 성공"으로는 완전히 충족하지 못한다 - 카탈로그
  데이터 자체의 공백 때문이며, 테스트 코드의 결함이 아니다.
- `향긋한`처럼 동일 텍스트가 여러 개념에 매핑되는 중의적 유사어(`review_required=True`)
  케이스는 기존 테스트(`test_resolve_marks_ambiguous_synonym_for_review`)가 이미 커버하므로
  중복 추가하지 않았다.

## 다른 트랙이 해야 할 일

- **CONTRACTS 트랙** (`src/meet_ai/ontology/**` 소유): 실제 서비스에서 영문(en-US) 사용자
  질의를 지원할 계획이라면 `catalog.v1.json`의 `synonyms` 배열에 `locale: "en-US"` 항목을
  추가해야 한다. 추가되면 본 파일의 `test_resolve_en_locale_has_no_synonym_coverage_yet`
  테스트의 기대값(0건 매치)이 깨지므로 그 시점에 QA_SECURITY 또는 담당 트랙이 실제 영문
  매칭 성공 케이스로 교체해야 한다.
- **AI_SEARCH 트랙**: 키오스크/웹 자연어 검색이 실제로 영문 질의를 받는 요구사항인지
  `docs/redesign-v2/common/C-3-ontology.md`, `kiosk/K-*` 문서를 근거로 재확인 필요 - 현재
  카탈로그에 영문 커버리지가 0이므로, 만약 요구사항이라면 이는 AIS-GROUP-001(Wave 2) 이전에
  선결돼야 할 데이터 공백이다.
