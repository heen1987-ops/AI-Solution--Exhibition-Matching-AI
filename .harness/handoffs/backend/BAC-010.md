## Summary

Implemented CR-001 guest web session APIs under `/api/v1/guest/sessions`.
The backend now exposes the WEB_ONLY session contract without extending the
deprecated `/api/v1/kiosk/*` implementation.

## Changed Files

- `backend/app/api/v1/endpoints/guest.py`
- `backend/app/api/v1/api.py`
- `backend/app/models/profile.py`
- `.harness/contracts/openapi.yaml`

## Public Interface

- `POST /api/v1/guest/sessions`
- `GET /api/v1/guest/sessions/{guest_session_id}`
- `POST /api/v1/guest/sessions/{guest_session_id}/favorites`
- `DELETE /api/v1/guest/sessions/{guest_session_id}/favorites/{temporary_favorite_id}`
- `POST /api/v1/guest/sessions/{guest_session_id}/convert`
- Legacy `POST /api/v1/guest/convert` remains as a compatibility wrapper.

## Behavior

- New guest sessions use `profile.guest_session(entry_channel='WEB')` and
  `device_type='MOBILE_WEB'`.
- Temporary favorites reuse `profile.saved_recommendable` through a
  `guest_session_id`-owned temporary `profile.user_profile`.
- Conversion moves temporary favorites to the registered profile when
  `transfer_temporary_favorites=true`.
- Expired guest sessions return `GUEST_SESSION_EXPIRED`.
- Invalid or used profile link tokens return `WEB_ENTRY_LINK_EXPIRED`.
- No name, phone, email, address, login ID, browser fingerprint, or new PII field
  was added.

## DB Changes

No migration was added. The implementation reuses existing
`profile.guest_session`, `profile.user_profile`, and `profile.saved_recommendable`
tables.
