## Behavior

- `GET /profile/me` requires a persistent profile context and returns
  `profile.user_profile`, active `profile.profile_attribute` rows, and
  `profile.buyer_need` when present.
- `PATCH /profile/me/attributes` requires a persistent profile context, checks
  `row_version`, resolves assignable active ontology codes, rewrites
  `USER_EDITED` attributes, increments profile versioning fields, and writes a
  `profile.profile_version` snapshot.
- `POST /guest/convert` requires `X-MeetAI-User-Id` for an existing active
  `profile.user_account`, validates the QR `entry_code`, records
  `guest_session.converted_user_id/converted_at`, clears the QR code, and moves
  guest-owned `UserProfile`/`VisitSession` rows to the registered user when
  possible.

## Guardrails

- `GUEST_WEB` cannot patch explicit profile attributes.
- Guest conversion does not create or update `identity.user_identity`; no name,
  phone, email, address, or login credential is collected.
- QR mismatch/expiry returns `QR_HANDOFF_EXPIRED`.
- Already converted sessions return `RESOURCE_CONFLICT`.
- Existing registered profiles are preserved; guest visit sessions are attached
  to the existing profile instead of overwriting explicit registered data.

## Known Limitations

The static frozen contract file did not already include an explicit
`/guest/convert` path, while the redesign roadmap (`W-8`, integration roadmap)
does. This implementation exposes the route in FastAPI OpenAPI and records the
contract-sync need for QA/contract follow-up rather than mutating the frozen
contract during a backend task.

DB-backed integration tests are not added here because `backend/tests/**` is
QA_SECURITY owned. A QA test request was created.
