# BAC-008 Backend Handoff

상태: DONE

## 구현

- `backend/app/api/v1/endpoints/search.py`
  - `POST /api/v1/search`
  - `POST /api/v1/guest/sessions/{guest_session_id}/search`
  - `POST /api/v1/search/clarify`
  - `GET /api/v1/search/{search_session_id}`
  - `GET /api/v1/recommendations`
  - `GET /api/v1/recommendations/{recommendation_session_id}`
- `backend/app/api/v1/api.py`
  - search router 등록.
- `backend/tests/test_search_api.py`
  - OpenAPI route registration, auth short-circuit, guest session id validation, recommendations auth smoke.

## 동작 계약

- 검색은 `matching.search_session`, `matching.search_query`, `matching.search_result`에 저장된다.
- 현재 실행 provider는 AIS-009 계약대로 `StructuredSearchProvider`만 READY다.
- `ReciprocalRankFusionCombiner`로 검색 후보를 결합하고 최대 20개를 응답한다.
- `decide_search_recovery` 결과가 `SearchResponse.meta`와 `matching.search_query.fallback_reason`에 반영된다.
- STRUCTURED 외 `KEYWORD`, `VECTOR`, `POPULAR`은 후속 provider query adapter 전까지 `unavailable_providers`로만 노출한다.
- 검색 세션 replay/clarify는 등록 사용자 프로파일 소유권, operator preview 소유권, 또는 유효한 게스트 세션을 확인한다.
- 추천 세션 replay는 `RecommendationSession.profile_id`와 요청 컨텍스트 프로파일이 일치해야 한다.
