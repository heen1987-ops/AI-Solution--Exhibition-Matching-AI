## Public Interface

Buyer endpoints require `X-MeetAI-User-Type: BUYER_REGISTERED` and
`X-MeetAI-Profile-Id`.

Meeting status updates allow:

- Buyer-owned request cancellation.
- Operator/admin acceptance, rejection, or exhibitor-side cancellation via
  `X-MeetAI-Actor-Role: OPERATOR` or `ADMIN` plus `X-MeetAI-User-Id`.

## Behavior

- `GET /buyer/matches` reads the latest `matching.recommendation_session` for the
  buyer profile and returns paginated `matching.match_result` rows with reasons.
- `POST /buyer/matches/{exhibitor_id}/meetings` creates `interaction.meeting`
  with status `REQUESTED` only for approved exhibitors with approved,
  consultation-enabled participation.
- `PATCH /meetings/{meeting_id}/status` accepts the exposed Web MVP transitions
  from `REQUESTED` to `CONFIRMED`, `REJECTED`, `CANCELLED_BY_BUYER`, or
  `CANCELLED_BY_EXHIBITOR`.
- `CONFIRMED` creates or completes `interaction.meeting_contact_share`; before
  confirmation, `contact_disclosed` is false.

## Guardrails

- Contact details themselves are not returned.
- Unapproved or non-consultation exhibitors are reported as
  `EXHIBITOR_NOT_PUBLISHED`.
- Invalid transitions return `INVALID_STATE_TRANSITION`.
- The API does not expose availability-slot scheduling, meeting outcomes,
  follow-up actions, CRM, contracts, payments, or precise booth scheduling.

## Known Limitations

`CreateMeetingRequest.message` is validated but not persisted because no
application encryption adapter exists yet. The implementation avoids storing
plaintext in `interaction.meeting.message_enc`. Add encrypted message persistence
only when the encryption/KMS adapter is available.

DB-backed integration tests are not added here because `backend/tests/**` is
QA_SECURITY owned. A QA test request was created.
