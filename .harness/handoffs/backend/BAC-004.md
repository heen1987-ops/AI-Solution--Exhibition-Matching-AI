# BAC-004 Handoff

Date: 2026-08-02
Track: BACKEND

## Completed

Implemented the admin content approval API:

- `POST /api/v1/admin/content-approvals`

The endpoint records an `ai.content_approval` document-level approval and
updates `exhibition.exhibitor.master_approval_status` to the requested decision.
It requires an existing operator/admin actor and an existing source document for
the exhibitor.

## Changed Files

- `backend/app/api/v1/endpoints/admin.py`
- `backend/app/api/v1/api.py`
- `backend/app/api/v1/dependencies.py`

## Public Interface

Request body follows CTR-002:

- `exhibitor_id`
- `decision`: `APPROVED` or `REJECTED`
- `note`

Local/test authorization headers:

- `X-MeetAI-User-Id`
- `X-MeetAI-Actor-Role: OPERATOR` or `ADMIN`

## Behavior

- Non-operator actors receive `PERMISSION_DENIED`.
- Missing operator user id receives `AUTHENTICATION_REQUIRED`.
- Missing exhibitor receives `RESOURCE_NOT_FOUND`.
- Missing source document receives `RESOURCE_NOT_FOUND`; the API does not create
  approval history without source evidence.
- Approval is explicit operator action only. No AI auto-approval was added.

## DB Changes

No schema changes. Uses CTR-007 `ai.content_approval` and existing
`exhibition.exhibitor.master_approval_status`.
