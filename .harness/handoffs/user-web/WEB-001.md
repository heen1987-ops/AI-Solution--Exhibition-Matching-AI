# WEB-001 인계 문서 - apps/user-web 라우트 뼈대 (Mock 데이터)

## 완료 내용

`apps/user-web/`에 Next.js 16(App Router) + TypeScript(strict) + Tailwind CSS 4 앱을
`create-next-app`으로 부트스트랩한 뒤 npm workspaces 멤버(`@backju/user-web`)로 편입했다.

- `/` - 사용자 웹 준비 화면(실제 개인화 홈이 아님, 빌드·기동 성공 안내 + `/health`·화면
  뼈대로 이동하는 링크만 제공).
- `/health` - 프런트엔드 빌드/환경 상태 화면. `NEXT_PUBLIC_API_BASE_URL`,
  `NEXT_PUBLIC_APP_ENV` 설정 여부를 점검해 OK/경고 배지를 보여준다. 백엔드를 실제로
  호출하지 않는 정적 상태 표시다.
- `docs/redesign-v2/web/W-3-screen-ia.md` S-1~S-8 전 화면을 라우트 그룹 `app/(screens)/`
  아래 Mock 데이터로 렌더링:
  - S-1 `/home` (개인화 홈), S-2 `/recommendations` (추천 목록, `?state=empty|error` 쿼리로
    빈 결과/오류 시나리오 재현 가능), S-3 `/search` (자연어 검색 - 클라이언트 필터링만
    흉내, GUEST_WEB 기본 비활성 원칙을 안내 문구로 명시), S-4 `/favorites` (관심목록,
    `?state=empty` 지원), S-5 `/companies/[companyId]` (업체·부스 상세, 존재하지 않는 id는
    `notFound()`로 404), S-6 `/buyer-matching` (바이어 매칭 - 상담 수락 전 연락처 비공개
    규칙을 데이터·렌더링 양쪽에 반영), S-7 `/my` (MY 정보, 로컬 폼), S-8 `/signup`
    (회원 전환 폼 스텁, 제출해도 실제 계정 생성 없음).
  - 모든 화면 상단에 "Mock 데이터만 사용" 배너를 노출해 실 API 미연동 상태를 화면에서도
    자기설명하게 했다.
- 공용 로딩/빈결과/오류 상태 컴포넌트(`components/StateViews.tsx`: `LoadingSkeleton`,
  `EmptyState`, `ErrorNotice`, `StatusBadge`)를 만들어 여러 화면에서 재사용. App Router
  `loading.tsx`(home/recommendations/favorites)·`error.tsx`(recommendations)로 실제
  Suspense/오류 경계 동작을 시연한다.
- `apps/user-web/.env.example` 제공 (`NEXT_PUBLIC_API_BASE_URL`, `NEXT_PUBLIC_APP_ENV`).
  주의: 템플릿 `.gitignore`의 `.env*` 규칙이 `.env.example`까지 가리는 문제를 발견해
  `!.env.example` 예외를 추가했다(다른 apps/* 스캐폴딩 시 동일 문제 주의).
- 실제 백엔드 API를 전혀 호출하지 않는다 - `lib/mock-data.ts`(하드코딩 데이터,
  `approvalStatus: "APPROVED"`만 사용해 AGENTS.md §8 원칙을 미러링)와
  `lib/mock-api.ts`(인위적 지연 + `empty`/`error` 시나리오 분기)만 사용한다.

## 테스트

Vitest(+ `@testing-library/react`, jsdom)를 채택했다 - 이유: 저장소에 기존 TS 테스트
러너 관행이 없어(루트 tsconfig는 `netlify/**/*.ts`만 대상), Next.js/React 생태계
표준으로 자리잡은 조합을 선택(`vitest.config.mts` 주석에도 기록). 다른 apps/* 앱이
동일 관행을 따르길 권장.

## 알려진 제한

- 사용자 유형(`GENERAL_REGISTERED`/`BUYER_REGISTERED`/`GUEST_WEB`) 분기는 실제 인증이
  아니라 `lib/mock-data.ts`의 `currentMockProfile` 하드코딩으로만 흉내낸다 - 실제 접근
  제어(예: GUEST_WEB의 S-1/S-4/S-6/S-7 차단)는 구현하지 않았다.
- S-3 자연어 검색은 이름/카테고리/태그 문자열 포함 여부만 보는 클라이언트 필터링이며
  실제 자연어 의도 추출(C-2)과 무관하다.
- S-8 회원 전환, S-7 MY 정보 수정, S-5 관심 저장, S-6 상담 요청은 모두 로컬 state만
  바꾸는 시각적 스텁 - 어떤 것도 서버에 저장되지 않는다.
- `vitest`의 `.rejects.toThrow(문자열)` 매처가 이 워크스페이스에서 루트에 호이스팅된
  `chai@5.3.3`과 상호작용해 `Cannot read properties of undefined (reading 'indexOf')`를
  던지는 현상을 발견했다(다른 apps/*의 다른 vitest 버전과 동시 설치되는 npm workspaces
  호이스팅 이슈로 추정, WEB-001 범위 밖). 회피책으로 해당 테스트를 try/catch 방식으로
  재작성했다(`tests/recommendations-page.test.tsx` 주석 참고) - QA_SECURITY/FOUNDATION이
  전체 workspace의 vitest 버전을 통일할지 검토할 가치가 있다.
- `packages/shared-types` 등 아직 없는 공유 타입 패키지 대신 앱 로컬
  `lib/types.ts`를 임시로 사용 - 계약 확정 후 교체 대상.

## 되돌리는 방법

`apps/user-web/` 디렉터리를 통째로 삭제하고 루트 `package-lock.json`에서 관련 항목을
제거한 뒤(`npm install`을 다시 실행하면 자동 정리됨), 이 인계 파일
(`.harness/handoffs/user-web/WEB-001.md`)을 삭제하면 된다. 다른 트랙 소유 경로는
건드리지 않았으므로 별도 조치가 필요 없다.
