# KSK-001

## 완료 내용

`apps/kiosk/`에 Next.js 14.2.35 / React 18.3 / TypeScript / Tailwind CSS 3 기반의 키오스크 이식형 검색모듈 라우트 뼈대를 신규 생성했다. npm workspaces 멤버로 `@backju/kiosk`(루트 `package.json`의 `workspaces: ["apps/*", "packages/*"]`가 이미 인식)로 등록된다. 이번 Wave는 라우트/레이아웃 스켈레톤 전용이며, 실제 익명 세션 생성(GuestSession)·자연어 검색 API(C-4)·실제 지도·QR 세션 인계는 의도적으로 구현하지 않았다(Mock/하드코딩 데이터만 사용).

라우트(`docs/redesign-v2/kiosk/K-3-screen-ia.md` §1 K-S1~K-S8 + 이번 Wave 필수 `/health`):
- `/` - K-S1 대기화면. 언어 순환 문구(정적 배열 스텁) + "시작하기" 버튼만 존재, 입력 필드 없음.
- `/language` - K-S2 언어 선택. 4개 언어 버튼(한/영/일/중), 텍스트 입력 없음.
- `/search` - K-S3 검색 진입. 자연어 검색창(`type="search"`, 서버 미전송) + 인기 카테고리 버튼. K-1-service-scope.md §2가 허용하는 유일한 텍스트 입력(자연어 질의)만 존재.
- `/results` - K-S4 결과 목록. Mock 업체 4건 카드 목록 + 빈 결과 상태(K-3 §2-1: "결과 없음"은 K-S8이 아니라 K-S4의 한 상태 - `ResultsScreen`이 `exhibitors=[]}`를 받으면 empty state를 렌더링하도록 구현, 별도 라우트를 만들지 않음).
- `/exhibitors/[id]` - K-S5 업체·부스 상세. Mock 상세 정보 + 지도/QR 이동 버튼.
- `/map` - K-S6 지도. 정밀 실내 내비게이션 없이(PROJECT_SCOPE.md 제외범위) 구역(zone) 단위 placeholder 그리드만 표시.
- `/qr` - K-S7 QR 화면. Mock QR 자리표시자(SVG 격자) + "전화번호/이메일 입력이 필요하지 않다"는 문구 - 실제 단기 토큰 발급/세션 인계는 K-5 후속 과제로 명시.
- `/error` - K-S8 오류화면. `?variant=network|qr-handoff|generic` 3가지 상태(K-3 §2의 네트워크 단절/QR 인계 실패 + 범용) 골격.
- `/health` - 키오스크 설정·API 연결상태. 디바이스 zone/id/유휴타임아웃(env 기반) 표시 + 공통 백엔드(`BAC-001` `/health/live`) 연결 시도(3초 타임아웃, 실패해도 예외 없이 "연결 안됨"으로 표시).

세션 타임아웃 상태기계 골격(`.harness/worker-prompts.md` KIOSK-003/004 패턴):
- `src/lib/session/session-machine.ts` - 순수 리듀서. `idle -> active -> timeout-reset -> idle` 전이만 정의(`SESSION_START`/`USER_ACTIVITY`/`IDLE_TIMEOUT`/`USER_FINISHED`/`QR_HANDOFF_COMPLETE`/`RESET_COMPLETE`). K-3-screen-ia.md §3의 "대기화면 도달은 (a)완료버튼 (b)타임아웃 (c)QR 인계완료 3가지 트리거로만" 원칙을 그대로 상태기계에 반영(세 이벤트 모두 `timeout-reset`으로 수렴). `resolveIdleTimeoutMs()`가 env 값을 60~120초 범위로 방어(K-1 §4 근거).
- `src/lib/session/use-session-timeout.ts` - 위 리듀서에 실제 `setTimeout`/사용자 활동 이벤트(`pointerdown`/`keydown`/`touchstart`)를 연결하는 훅. `timeout-reset` 진입 시 `onClearSessionData` 콜백(클라이언트 `sessionStorage.clear()`)을 호출해 다음 이용자에게 이전 세션 데이터가 남지 않게 한다.
- `src/components/kiosk/SessionTimeoutProvider.tsx` - 위 훅을 앱 전역(`layout.tsx`)에 연결하는 Context Provider. 타임아웃 도달 시 `router.push("/")`로 대기화면 복귀.
- 실제 백엔드 `GuestSession.expires_at` 연동, 실제 서버 세션 폐기 API 호출은 이번 Wave 범위 밖(스켈레톤이라는 태스크 지시사항 그대로).

**개인정보 입력 부재 검증(가장 중요, AGENTS.md §8 / PROJECT_SCOPE.md 키오스크 제외범위)**:
- `src/__tests__/no-personal-data-input.test.tsx`가 이번 Wave에서 스캐폴딩한 9개 화면 컴포넌트(K-S1~K-S8 전부 + `/health`, 오류화면은 3개 variant 모두 별도 케이스) 전부를 렌더링하고, 각 렌더 결과에서 `input`/`textarea`/`select` 전부를 순회하며:
  1. `type="password"|"email"|"tel"` 금지
  2. `autocomplete`가 `email`/`tel`/`name`/`username`/`current-password`/`cc-number` 등 개인정보 계열 값이면 금지
  3. `name`/`id`/`placeholder`/`aria-label`이 이메일/전화/비밀번호/로그인/주민등록번호/카드번호 등 한/영 키워드 정규식과 일치하면 금지
  4. `<form>` 내부에 비밀번호 입력이 없는지 확인
  을 단언한다. 검증 헬퍼 자체가 실제로 위반을 탐지하는지 확인하는 반증 테스트(가짜 `type="email"` 폼을 렌더링해 검증 함수가 `throw`하는지 확인)도 포함해, 테스트가 항상 통과만 하는 무력한 검증이 아님을 보장했다.
- K-S3(자연어 검색)의 `type="search"` 입력은 K-1-service-scope.md §2가 명시적으로 허용하는 유일한 텍스트 입력(현재 자연어 질의)이므로 위 정규식과 의도적으로 충돌하지 않게 설계했다(검색어 자체는 개인정보가 아님).

## 알려진 제한

- 실제 익명 세션(GuestSession) 생성/폐기, 실제 자연어 검색 API(C-4) 연동, 실제 지도 좌표/경로, 실제 QR 단기 토큰 발급은 없음(의도된 스코프 - 이번 Wave는 "route/layout 스켈레톤"만).
- `/health`의 백엔드 연결상태 확인은 `NEXT_PUBLIC_API_BASE_URL`이 가리키는 곳에 실제로 `fetch`를 시도한다(이 화면 본연의 목적이 연결상태 표시이므로) - 로컬에서 backend가 기동되어 있지 않으면 "연결 안됨"으로 표시되는 것이 정상이며, 이는 버그가 아니다.
- 세션 타임아웃 골격은 순수 프런트엔드 타이머일 뿐 서버 `GuestSession.expires_at`과 연동되지 않는다 - 백엔드 세션 개념이 확정되면(BAC 트랙) 실제 연동이 필요하다.
- `/error`의 3-variant는 이번 Wave에서는 `?variant=` 쿼리 파라미터로만 진입 가능한 정적 화면이다 - 실제 네트워크 단절/QR 인계 실패 감지 로직과는 아직 연결되지 않았다.
- Tailwind 클래스 `min-h-touch`/`text-kiosk`/`text-kiosk-lg`는 `tailwind.config.ts`에 정의한 이 앱 전용 토큰(터치 타깃/큰 글씨 기준) - 다른 앱과 공유되지 않는다(공유 UI 토큰화는 `packages/ui/**` 소유권이 정해지는 Wave 2 이후 논의 대상, `.harness/locks.yaml` 주석 참고).

## 되돌리는 방법

`apps/kiosk/` 전체가 신규 디렉터리이므로 `git rm -r apps/kiosk/`(또는 아직 커밋 전이면 단순 디렉터리 삭제)로 완전히 되돌릴 수 있다. 부수효과인 루트 `package-lock.json` 변경은 `git checkout -- package-lock.json` 후 `npm install`로 재생성하면 되지만, 다른 트랙(`apps/admin`, `apps/user-web` 등)이 추가한 의존성까지 함께 사라질 수 있으니 되돌리기 전 다른 트랙의 workspace 의존성 유무를 먼저 확인할 것.
