# AIS-009 Handoff - FTS·Vector Provider 계약 및 BAC-008 연결 순서

상태: DONE

## 변경 요약

- `backend/app/services/matching/search_pipeline_contract.py`를 추가했다.
- KeywordSearchProvider의 FTS 대상 필드, rank normalization, `keyword_score`, unavailable fallback을 고정했다.
- VectorSearchProvider의 `ai.embedding_document`/`ai.embedding_vector` 연결 조건, query embedding adapter 필요조건, `semantic_score`, unavailable fallback을 고정했다.
- BAC-008 검색 파사드가 따라야 할 provider/recovery/persistence 순서를 `BAC008_SEARCH_PIPELINE`으로 명시했다.
- 실제 FTS GIN index, pgvector ANN index, legacy `matching.search_session.channel` CHECK 정렬은 CTR-012 후속으로 분리했다.

## BAC-008 연결 계약

1. actor 검증: REGISTERED_WEB/BUYER_WEB user 또는 GUEST_WEB guest_session을 PII 없이 확인.
2. intent 해석: 자유텍스트는 AIS-005 schema를 통과한 값만 사용하고 원문에 없는 concept를 만들지 않음.
3. SearchQuery 구성: channel, raw_text, locale, required/preferred/excluded concept_id를 보존.
4. provider 실행: 기본은 STRUCTURED만 READY. KEYWORD/VECTOR/POPULAR은 readiness가 READY일 때만 실행.
5. RRF 결합: `ReciprocalRankFusionCombiner` 사용.
6. 회복 정책: `decide_search_recovery`를 적용하고 `fallback_reason_for_recovery`로 persistence 값을 결정.
7. 저장: `matching.search_session/search_query/search_result`.
8. 응답: `SearchResponse.results` 및 필요 시 `meta.code=SEARCH_NO_RESULT`.

## 후속

CTR-012가 BAC-008 선행조건이다. 현재 `matching.search_session.channel` CHECK는 legacy `WEB/KIOSK`라 GUEST_WEB persistence 전에 migration 정렬이 필요하다. FTS/vector provider도 실제 활성화를 위해 GIN/ANN index와 query embedding adapter가 필요하다.
